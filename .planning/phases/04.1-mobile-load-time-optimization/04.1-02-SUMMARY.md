## What was built

### `src/lib/thumbnail-url.ts` (helper)

Public API (synchronous, non-blocking):
- `getThumbnailUrl(url: string, width = 200, quality = 70): string`
- `resetThumbnailTierCacheForTests(): void` (test-only)

Tier state machine (module-scope, in-memory, app-lifetime):
```
unknown  ──(first Supabase URL call)──►  detecting  ──(HEAD 200)──►  available
                                             │
                                             └──(HEAD 4xx / network err)──► unavailable
```

- While `unknown` / `detecting` / `unavailable`: return original URL unchanged.
- Only when `available`: rewrite `/storage/v1/object/public/…` → `/storage/v1/render/image/public/…?width=…&quality=…`.
- Data URIs and non-Supabase URLs: pass-through, never trigger detection.

### Test coverage (16 tests)

**Suite A: pure URL rewriting (4)**
- A1 pass-through data URI
- A2 pass-through non-Supabase HTTPS
- A3 pass-through empty string
- A4 pass-through null (no throw)

**Suite B: tier detection behavior (12)**
- B1 initial call → returns original + kicks off ONE HEAD probe
- B2 concurrent in-flight calls → all return originals + still only ONE HEAD
- B3 HEAD 200 resolves → tier `available` → subsequent calls return transformed URL
- B4 HEAD 400 resolves → tier `unavailable` → all subsequent calls stay on originals
- B5 HEAD rejects (network error) → same as B4
- B6 custom width/quality honored when transforming
- B7 URL with existing `?token=…` query gets transform appended with `&` (one `?` preserved)
- B8 rewrites `/object/public/` → `/render/image/public/` when transforming
- B9 detection probe URL targets `/render/image/public/` (regex-verified)
- B10 no HEAD probe for `data:` URIs even when tier is unknown
- B11 helper NEVER returns a Promise (sync contract guard)
- B12 `resetThumbnailTierCacheForTests` re-arms detection

## Expected runtime behavior on Free plan (verified via unit tests)

- User visits `/mis-plantas` for the first time.
- React mounts, first card renders. `getThumbnailUrl(url, 160)` is called on card 1.
  - Tier is `unknown` → helper returns the ORIGINAL URL immediately + kicks off a HEAD probe to `.../render/image/public/…?width=100&quality=70`.
  - Tier flips to `detecting`.
- Cards 2..N render in the same commit. `getThumbnailUrl` is called for each.
  - Tier is `detecting` (or already resolved by then) → each returns the ORIGINAL URL. Zero additional HEADs.
- HEAD probe resolves 400 (Free plan) → tier flips to `unavailable`.
- User navigates back and forth all session → tier stays `unavailable`, all card images use their original HTTPS Storage URL.

**Chrome DevTools expectations for CPO's manual smoke check:**
- Network panel filter `/render/image/`: exactly ONE request, response status 400 (or 404), size <1 KB. Shows the probe fired exactly once per session.
- Network panel filter `img`: only the first ~3-4 cards' images load initially. Scrolling triggers the rest. Priority column shows "Low" for lazy-loaded cards (correct); "High" would indicate lazy isn't applied.
- No broken image icons (since helper returns originals on Free).

## Expected runtime behavior if CPO upgrades to Pro later

Zero code change required. The HEAD probe on next session load returns 200 → tier caches `available` → all subsequent card renders emit `/render/image/public/…?width=160&quality=70` (History) or `?width=128&quality=70` (PlantWateringCard) URLs. Supabase returns 5-10× smaller JPEGs.
