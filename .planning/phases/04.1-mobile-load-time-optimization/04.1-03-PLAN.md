Public API of src/hooks/use-perf-screen-loaded.ts:
```typescript
export type PerfScreenName = "mis-plantas" | "regar" | "mapa";

/**
 * Fire PostHog event 'perf_screen_loaded' exactly once per component mount,
 * on the first render where isReady === true.
 *
 * TTFC (Time-to-First-Content) is measured as Math.round(performance.now())
 * at the effect execution time. This is a slight over-estimate of the true
 * first-paint (useEffect runs after commit but before browser paints images),
 * which is acceptable per D-10's ±25% tolerance — we want to include any
 * post-mount data-readiness lag in the number.
 *
 * @param screen  Static screen identifier for the event property.
 * @param isReady Whether the screen has content ready to display (typically !isLoading).
 * @param extraProps Additional event properties (e.g., { plants_count }). Flat only.
 */
export function usePerfScreenLoaded(
  screen: PerfScreenName,
  isReady: boolean,
  extraProps?: Record<string, unknown>,
): void;
```

    ```typescript
    import { useEffect, useRef } from "react";
    import { track } from "@/lib/track";

    export type PerfScreenName = "mis-plantas" | "regar" | "mapa";

    /**
     * Fire PostHog event 'perf_screen_loaded' exactly once per component mount,
     * on the first render where isReady === true.
     *
     * Measures Time-to-First-Content (TTFC) via performance.now() at the effect
     * time — a slight over-estimate of true first-paint (useEffect runs after
     * commit but before browser paints images). Acceptable per D-10 ±25%
     * tolerance; we WANT the number to include post-mount data lag.
     *
     * Uses useRef for the firing guard so mutation doesn't cause re-render.
     * Uses useEffect (NOT useLayoutEffect) so we don't block paint — critical
     * per anti-pattern documented in RESEARCH.md.
     *
     * Super-properties app_version + app_platform are added automatically by
     * initPostHog() → posthog.register() (D-13). Do NOT pass them explicitly.
     */
    export function usePerfScreenLoaded(
      screen: PerfScreenName,
      isReady: boolean,
      extraProps?: Record<string, unknown>,
    ): void {
      const fired = useRef(false);

      useEffect(() => {
        if (!isReady || fired.current) return;
        fired.current = true;
        const ttfc_ms = Math.round(performance.now());
        track("perf_screen_loaded", {
          screen,
          ttfc_ms,
          ...(extraProps ?? {}),
        });
        // Intentionally exhaustive deps disabled: we want to fire once, driven
        // by isReady transition. `screen` is stable per mount, `extraProps` is
        // captured at fire time (change after fire is ignored — the extraProps
        // in a re-render is the CURRENT value at fire moment).
        // eslint-disable-next-line react-hooks/exhaustive-deps
      }, [isReady]);
    }
    ```

    Create `src/hooks/use-perf-screen-loaded.test.ts` with all 9 test cases.

    Note on test 9: because our useEffect deps include only `[isReady]`, the effect only re-runs when isReady changes. So even if extraProps changes, the effect won't run again → no re-fire. That's the desired semantic (fire on ready transition, capture props at that moment).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → PostHog EU endpoint (`eu.i.posthog.com`) | Event payload leaves the user's device |
| Application code → track() | Event names and props defined in code, no user input flows into event names |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1.03-01 | Information Disclosure | Event payload contains user data / PII | mitigate | Payload contains ONLY: `screen` (enum literal), `ttfc_ms` (integer), `plants_count` (integer), plus super-props `app_version` + `app_platform` (both non-PII). No user IDs, no plant names, no coordinates, no email addresses. Payload is closed enum + integers only. |
| T-04.1.03-02 | Tampering | Malicious re-render could spam the event | mitigate | `useRef` firing-guard ensures exactly one fire per mount. Even if a parent re-renders 1000 times per second, `fired.current` short-circuits the effect after first fire. |
| T-04.1.03-03 | Information Disclosure | performance.now() as fingerprinting vector | accept | `performance.now()` resolution is intentionally coarsened by browsers post-Spectre (typically 100μs on modern browsers). This alone is insufficient for cross-user fingerprinting. Combined with app_platform + app_version, still not unique per user. |
