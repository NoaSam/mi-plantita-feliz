## What was built

### `src/hooks/use-perf-screen-loaded.ts` (hook)

Public API (fully synchronous):

```typescript
export type PerfScreenName = "mis-plantas" | "regar" | "mapa";

export function usePerfScreenLoaded(
  screen: PerfScreenName,
  isReady: boolean,
  extraProps?: Record<string, unknown>,
): void;
```

Semantics:

1. When `isReady === false`: does nothing.
2. When `isReady === true` on first pass through the effect: fires `track("perf_screen_loaded", { screen, ttfc_ms, ...extraProps })`, flips `fired.current = true`.
3. All subsequent runs of the effect (isReady changing back or extraProps changing) short-circuit on `fired.current`.
4. New mount = new hook instance = `fired.current` starts at `false` again → fresh fire allowed.

Key implementation notes (verified in file):

- **useEffect NOT useLayoutEffect** — `src/hooks/use-perf-screen-loaded.ts:38`. Documented anti-pattern in RESEARCH.md (Pitfall 4): useLayoutEffect blocks paint.
- **useRef firing-guard** — `src/hooks/use-perf-screen-loaded.ts:36`. Cheaper than useState (no re-render on mutation).
- **Math.round(performance.now())** — rounds fractional ms to integer. Test 5 covers the rounding.
- **Effect deps: `[isReady]` only** — screen is static per mount; extraProps captured at fire moment. `eslint-disable-next-line react-hooks/exhaustive-deps` documented inline.

### Test coverage (9 tests)

1. Does NOT fire when `isReady=false`
2. Fires once when `isReady=true` on first render with correct `{screen, ttfc_ms, plants_count}`
3. Fires on false → true transition

## Expected runtime behavior

On production (post-deploy, PostHog initialized with user consent):

- User navigates to `/mis-plantas` → History mounts → `usePlantHistory` fetches → `isLoading` becomes `false` → next effect tick fires `track("perf_screen_loaded", { screen: "mis-plantas", ttfc_ms: <integer>, plants_count: N })`.
- Super-props `app_version` (from `__APP_VERSION__` define) and `app_platform` (`"web"` or `"android"`) attached automatically via `posthog.register()`.
- User re-navigates back and forth → new mount each time → new event each time (correct — each visit is a separate perf measurement).
- User re-renders same mount (e.g., toggle edit mode in History) → NO re-fire (fired guard).

On dev (`npm run dev` on localhost):

- `initPostHog()` no-ops on localhost (see `src/lib/track.ts:42`).
- `track()` no-ops when `initialized === false`.
- **The hook still runs**, `performance.now()` still computes, but the network call is suppressed. Expected and by design.
