# Phase 03.1: Plant Map v0 — Research

**Researched:** 2026-05-16
**Domain:** React mobile map UI sobre Leaflet/OSM en stack dual-shell (Capacitor 8 WebView Android + PWA iOS Safari 16+)
**Confidence:** HIGH

## Summary

Esta fase es una integración de Leaflet + react-leaflet sobre el design system existente, con una nueva ruta `/mapa`, un nuevo bottom sheet, un nuevo hook de query y una refactorización pequeña del `BottomTabBar` para soportar tabs condicionales. **El stack está completamente lockeado en CONTEXT.md** (17 decisiones D-01 a D-17); el trabajo del researcher es validar que cada elección sigue siendo correcta en mayo 2026 y producir guidance accionable para el planner. Investigación primaria: npm registry (versiones actuales), react-leaflet docs oficiales, Leaflet 1.9.4 API reference y OSMF Tile Usage Policy.

**Conclusiones clave:**
- `react-leaflet@4.2.1` es la **última versión** de la rama 4.x (publicada Feb 2023, sin actualizaciones desde entonces). Es la rama correcta para React 18.3.1: v5.0.0 (Dic 2024) requiere React 19 como peer dep, lo cual rompería este proyecto.
- Las defaults de marker de Leaflet (`marker-icon.png`, `marker-shadow.png`) tienen un bug conocido con Vite en producción: **no aplica a esta fase** porque D-09 usa `L.divIcon` exclusivamente (no `L.icon` default). Confirmar en runtime que no hay 404s residuales.
- shadcn `Sheet` (Radix Dialog `side="bottom"`) **no incluye drag-to-close nativo**; cierre vía botón "Cerrar" + tap-en-overlay + tecla Esc. `vaul` (ya instalado pero no usado) sí lo soporta, pero CONTEXT.md D-08 explicita `Sheet` shadcn — respetar lock.
- OSM Tile Usage Policy (válida hoy) requiere atribución visible **siempre**, prohíbe pre-fetch/bulk download de tiles y exige cumplir cache headers. Mantener tile attribution renderizada por Leaflet vía `TileLayer attribution` prop; no añadir runtime caching del tile host en el SW.
- El proyecto **NO usa `@tanstack/react-query` en `src/`** aunque la dependencia está instalada (cero matches de `useQuery`). Mantenerse en el patrón establecido (hook con `useState`/`useEffect` + `refetch` manual, como `useUnclassifiedCount`) para consistencia. Introducir React Query en esta phase desviaría del patrón sin beneficio claro para 1 query simple.

**Primary recommendation:** Stack lockeado es correcto; instalar `leaflet@^1.9.4 react-leaflet@^4.2.1 @types/leaflet@^1.9.21`, importar `leaflet/dist/leaflet.css` en `src/main.tsx` antes de `./index.css`, usar pattern `useMap()` desde un hijo `<FitBoundsOnMount pins={...}/>` para `fitBounds`/`setView`, y replicar el patrón de hook de `useUnclassifiedCount.ts` para `use-wild-plants-with-coords.ts` y `use-context-counts.ts`. No usar React Query.

### Pattern 1: Hook con `useState`/`useEffect` + `refetch` (PATRÓN ESTABLECIDO — replicar)

**What:** Hook custom que ejecuta una query Supabase, maneja loading/error, expone `refetch` para invalidación manual.
**When to use:** Toda query a Supabase en este proyecto (per `usePlantHistory`, `useUnclassifiedCount`, `usePlantById`).
**Example (skeleton para `use-wild-plants-with-coords.ts`):**

```typescript
// Source: pattern derived from src/hooks/use-unclassified-count.ts (lines 19-79)
import { useCallback, useEffect, useRef, useState } from "react";
import { supabase } from "@/integrations/supabase/client";
import { useAuth } from "@/hooks/use-auth";

export interface WildPlantWithCoords {
  id: string;
  name: string;             // common_name (en este schema es "name", scientific debajo)
  imageUrl: string;
  lat: number;              // narrowed: hook garantiza no-null
  lng: number;              // narrowed: hook garantiza no-null
  createdAt: string;
  description: string;      // necesario para sheet preview (extraer scientific de aquí si applica)
  context: 'wild';
}

export interface UseWildPlantsWithCoordsReturn {
  plants: WildPlantWithCoords[];
  isLoading: boolean;
  refetch: () => Promise<void>;
}

export function useWildPlantsWithCoords(): UseWildPlantsWithCoordsReturn {
  const { user } = useAuth();
  const [plants, setPlants] = useState<WildPlantWithCoords[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const mountedRef = useRef(true);
  useEffect(() => {
    mountedRef.current = true;
    return () => { mountedRef.current = false; };
  }, []);

  const load = useCallback(async () => {
    if (!user) {
      if (!mountedRef.current) return;
      setPlants([]);
      setIsLoading(false);
      return;
    }
    const { data, error } = await supabase
      .from("plant_searches")
      .select("id, name, image_url, lat, lng, created_at, description")
      .eq("user_id", user.id)
      .eq("context", "wild")
      .not("lat", "is", null)
      .not("lng", "is", null)
      .order("created_at", { ascending: false });

    if (!mountedRef.current) return;
    if (error) {
      console.error("Error fetching wild plants with coords:", error.message);
      setPlants([]);
      setIsLoading(false);
      return;
    }
    setPlants(
      (data ?? []).map((row) => ({
        id: row.id,
        name: row.name,
        imageUrl: row.image_url,
        lat: row.lat as number,
        lng: row.lng as number,
        createdAt: row.created_at,
        description: row.description,
        context: 'wild' as const,
      })),
    );
    setIsLoading(false);
  }, [user]);

  useEffect(() => { load(); }, [load]);
  return { plants, isLoading, refetch: load };
}
```

### Pattern 2: `useMap()` hijo para imperativos sobre el mapa (RECOMENDADO)

**What:** Componente hijo de `<MapContainer>` que usa `useMap()` hook para acceder a la instancia `L.Map` y ejecutar `fitBounds`/`setView`.
**When to use:** Cualquier operación imperativa sobre el mapa (zoom, center, layers dinámicos).
**Why:** react-leaflet@4 ya **no** soporta `whenCreated`; el patrón canónico es children-with-`useMap()`. [CITED: https://react-leaflet.js.org/docs/example-view-bounds/]

**Example:**

```typescript
// Source: react-leaflet v4 official docs (example-view-bounds)
import { useEffect } from "react";
import { useMap } from "react-leaflet";
import L from "leaflet";

interface FitBoundsOnMountProps {
  pins: Array<{ lat: number; lng: number }>;
}

export function FitBoundsOnMount({ pins }: FitBoundsOnMountProps) {
  const map = useMap();
  useEffect(() => {
    if (pins.length === 0) return;
    if (pins.length === 1) {
      map.setView([pins[0].lat, pins[0].lng], 14); // D-15 zoom city-level
      return;
    }
    const bounds = L.latLngBounds(pins.map(p => [p.lat, p.lng]));
    map.fitBounds(bounds, { padding: [40, 40] }); // D-14
  }, [map, pins]);
  return null;
}
```

Uso en `MapPage`:
```typescript
<MapContainer center={[40.4168, -3.7038]} zoom={13} style={{ height: "100%", width: "100%" }}>

    url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png"

NO intentes pasar `center={dynamicCenter}` esperando que cambie. [CITED: https://react-leaflet.js.org/docs/api-map/ — "Except for its children, MapContainer props are immutable"]

### Anti-Patterns to Avoid

- **❌ NO usar `whenCreated` prop en `<MapContainer>`.** Removido en react-leaflet v4. Usar `<FitBoundsOnMount>` hijo con `useMap()`. [VERIFIED: react-leaflet v4 changelog — see WebSearch result on whenCreated removal]
- **❌ NO pasar `center` dinámico al `<MapContainer>` esperando re-center.** `MapContainer` props son **inmutables después de mount** excepto children. [CITED: https://react-leaflet.js.org/docs/api-map/]
- **❌ NO usar React `<StrictMode>` envolviendo `<MapContainer>`.** react-leaflet tiene incompatibilidad documentada con StrictMode (doble mount → mapa "fantasma"). [CITED: https://react-leaflet.js.org/docs/start-introduction/ — "React's Strict Mode is noted as incompatible"]. **Status del proyecto:** `src/main.tsx` NO usa StrictMode (verificado), así que esto NO es un blocker — pero asegurar que el planner no lo añada.
- **❌ NO añadir runtime caching de tiles OSM en el SW.** Viola OSM Tile Usage Policy ("offline use is not permitted on tile.openstreetmap.org"). [CITED: https://operations.osmfoundation.org/policies/tiles/]
- **❌ NO ocultar la atribución con CSS** (e.g., `.leaflet-control-attribution { display: none }`). Viola la licencia ODbL. Atribución debe ser visible y legible.
- **❌ NO usar emoji o caracteres especiales en el `attribution` HTML sin escapar.** Leaflet renderiza el string como innerHTML. Usar `&copy;` no `©`, `&nbsp;` no espacio raro.
- **❌ NO importar `leaflet` antes del CSS.** Si importas `import L from "leaflet"` antes de `import "leaflet/dist/leaflet.css"`, la primera renderización puede tener tiles dimensiones rotas. Importar CSS en `src/main.tsx` (antes de `./index.css`) garantiza orden correcto.
- **❌ NO renderizar `<MapContainer>` con `height: 0` o sin altura explícita.** Leaflet calcula `mapSize` al mount; si el contenedor mide 0px, el mapa queda blanco hasta un `invalidateSize`. Pasar `style={{ height: "100%", width: "100%" }}` Y asegurar que el padre tenga altura explícita (calc del viewport menos header/tab bar). Ver § "Implementation guidance → R4" para detalle.

## Cross-Platform Pitfalls

Esta sección es **load-bearing**: cada decisión técnica debe validarse en (a) Capacitor 8.3.1 WebView Android, (b) Safari iOS 16+ PWA standalone, (c) navegadores móviles modernos.

### Android (Capacitor 8 WebView)

**Build path:** `npm run android` → `VITE_CAPACITOR=true vite build` → `npx cap sync` → APK/AAB.

**Pitfalls verificados:**

1. **`base: './'` en `vite.config.ts`** está activo cuando `VITE_CAPACITOR=true` (verificado, líneas 7+10 de `vite.config.ts`). Esto significa todos los assets (incluido el CSS de leaflet importado) usan paths relativos. ✓ Compatible — `import "leaflet/dist/leaflet.css"` Vite lo procesa y lo inlinea/codifica con hash en el bundle final; no se rompe por path relativo. [VERIFIED: Vite docs § "Asset Handling" - relative paths preservados con base `./`]

2. **Service Worker desactivado** en build Android (líneas 17-19 de `src/main.tsx` y línea 20 de `vite.config.ts` que excluye `VitePWA` si `isCapacitor`). ✓ Esto significa que no hay que preocuparse por SW caching de tiles en Android. **Cero código a añadir aquí.**

3. **Pinch-zoom en Capacitor WebView Android** funciona con Leaflet por defecto (Leaflet detecta touch events vía `L.Browser.touch`). Pero hay un known issue de Chrome Mobile: después de pinch zoom, los touch events pueden no propagarse correctamente. [CITED: https://github.com/Leaflet/Leaflet/issues/6572] **Mitigación:** ninguna requerida para v0 — el caso típico es tap en pin, no panning intensivo. Si feedback negativo en QA, evaluar `Leaflet.GestureHandling` en v1+.

4. **Viewport del mapa en Android:** Capacitor inyecta `viewport-fit=cover` solo si está en `index.html`. Verificado: `index.html` línea 5 ya lo tiene. ✓ Safe area respetada.

5. **Status bar overlay:** `src/main.tsx` líneas 33-39 ya configura `StatusBar.setOverlaysWebView({ overlay: false })`. ✓ El mapa ocupa exactamente el viewport útil, no detrás del status bar.

6. **`L.divIcon` con HTML inline:** renderiza igual en Capacitor WebView 8 (que es Chrome 121+) y Safari iOS 16+ — testeado por multitud de proyectos. ✓ Sin pitfalls.

7. **Background del divIcon transparente:** Leaflet aplica clase default `.leaflet-div-icon` que tiene `background: white; border: 1px solid #666`. **Override obligatorio** con `.plant-map-pin { background: transparent !important; border: none !important; }` o else verás un cuadrado blanco + border gris alrededor del sticker.

### iOS (Safari 16+ PWA standalone)

**Build path:** `npm run build` (sin `VITE_CAPACITOR`) → deploy a Vercel → usuario instala PWA via "Add to Home Screen".

**Pitfalls verificados:**

1. **PWA standalone + viewport-fit=cover:** ya configurado en `index.html` (línea 5). Y `apple-mobile-web-app-capable=yes` (línea 7) + `apple-mobile-web-app-status-bar-style=black-translucent` (línea 8). ✓ El mapa se renderiza correctamente con safe area.

2. **Service Worker activo en iOS PWA:** `vite-plugin-pwa` se activa en build de iOS (no Capacitor). Su workbox config (líneas 24-29 de `vite.config.ts`) usa `globPatterns: ["**/*.{js,css,html,ico,png,svg,webp}"]` — esto cachea **assets buildados** del bundle, NO incluye `https://tile.openstreetmap.org/*` porque está fuera de origen. ✓ Cumple OSM Tile Usage Policy "no offline caching". **Importante:** NO añadir `runtimeCaching` para tiles OSM al config del PWA. [CITED: https://operations.osmfoundation.org/policies/tiles/]

3. **Safe area inset bottom en iOS PWA standalone:** El home indicator del iPhone X+ ocupa los últimos ~34px. Si el Sheet renderiza CTAs ahí, son tapeable-pero-incómodos.
   - **Solución:** El `SheetContent` debe tener `padding-bottom: max(1.5rem, env(safe-area-inset-bottom))` o usar la utility `pb-safe` ya definida en `tailwind.config.ts` (líneas 6-12). Patrón verificado en `BottomTabBar.tsx` línea 24 y `CookieConsentBanner.tsx` línea 42 — replicar.

4. **BottomTabBar safe area:** Ya lo tiene (`pb-safe` en línea 24 de `BottomTabBar.tsx`). ✓ Al añadir la 3ª/4ª/5ª tab no rompe; el `flex justify-around` se redistribuye. Pero **iPhone SE (375px width)** con 4-5 tabs queda muy apretado:
   - Cálculo: container `max-w-md` = 448px, en SE el viewport es 375px efectivo. Con 5 tabs cada una mide ~75px, icono+label cabe pero margen visual mínimo.
   - **Mitigación:** mantener labels cortos ("Mapa" no "Descubrimientos" — D-09 specific en CONTEXT.md ya lo hace). El planner debe testear en SE viewport (375px) durante implementación.

5. **shadcn Sheet drag-to-close NO existe.** Radix Dialog (la base de Sheet) **no implementa drag gesture**. Los usuarios iOS esperan "swipe down to dismiss" como en iOS sheets nativos. Para el mapa Leaflet, el scroll del propio mapa (panning) se controla por Leaflet — al estar el Sheet capa overlay sobre el mapa, los touch events del mapa quedan bloqueados por el overlay. ✓ Sin código adicional.

7. **Tile.openstreetmap.org en iOS Safari:** carga normal vía HTTPS, sin restricciones de mixed content (todo HTTPS). ✓

8. **iOS Safari PWA + Vite-plugin-pwa cache update:** `registerType: "autoUpdate"` (línea 23 vite.config.ts) más `skipWaiting: true` + `clientsClaim: true` (líneas 28-29) significa que cuando hay nuevo bundle, el SW se actualiza y `controllerchange` listener (main.tsx líneas 27-30) recarga la app. ✓ Cero código nuevo para esta phase.

```typescript
// src/hooks/use-context-counts.ts — NEW
import { useCallback, useEffect, useRef, useState } from "react";
import { supabase } from "@/integrations/supabase/client";
import { useAuth } from "@/hooks/use-auth";

export interface ContextCounts {
  home: number;
  wild_with_coords: number;
  wild_without_coords: number;
  unclassified: number;
}

export interface UseContextCountsReturn extends ContextCounts {
  isLoading: boolean;
  refetch: () => Promise<void>;
}

const ZERO: ContextCounts = { home: 0, wild_with_coords: 0, wild_without_coords: 0, unclassified: 0 };

export function useContextCounts(): UseContextCountsReturn {
  const { user } = useAuth();
  const [counts, setCounts] = useState<ContextCounts>(ZERO);
  const [isLoading, setIsLoading] = useState(true);
  const mountedRef = useRef(true);
  useEffect(() => {
    mountedRef.current = true;
    return () => { mountedRef.current = false; };
  }, []);

  const load = useCallback(async () => {
    if (!user) {
      if (!mountedRef.current) return;
      setCounts(ZERO);
      setIsLoading(false);
      return;
    }
    // Single SELECT + group manual (PostgREST no soporta GROUP BY directo en select).
    // Para 4 buckets podemos hacer 4 count queries pequeñas en paralelo o leer
    // (context, lat, lng) y agregar en cliente. Para <200 rows típicos del proyecto,
    // leer columnas relevantes es más simple y eficiente que 4 round-trips.
    const { data, error } = await supabase
      .from("plant_searches")
      .select("context, lat, lng")
      .eq("user_id", user.id);

    if (!mountedRef.current) return;
    if (error) {
      console.error("Error fetching context counts:", error.message);
      setCounts(ZERO);
      setIsLoading(false);
      return;
    }
    const agg: ContextCounts = { ...ZERO };
    for (const row of data ?? []) {
      if (row.context === 'home') agg.home += 1;
      else if (row.context === 'wild') {
        if (row.lat !== null && row.lng !== null) agg.wild_with_coords += 1;
        else agg.wild_without_coords += 1;
      } else agg.unclassified += 1;
    }
    setCounts(agg);
    setIsLoading(false);
  }, [user]);

  useEffect(() => { load(); }, [load]);
  return { ...counts, isLoading, refetch: load };
}
```

### R4: Render de pins en MapPage con divIcon custom

**Layout crítico:** El `MapContainer` necesita altura explícita. El padre (`AppLayout`) tiene `pb-20` (5rem, 80px) para el BottomTabBar. El header de la app NO existe en `/mapa` (solo el LegalFooter, pero MapPage no debe mostrar LegalFooter — distrae del mapa).

**Solución de altura:**

```typescript
// src/pages/MapPage.tsx — NEW
import { useEffect, useState } from "react";
import { MapContainer, TileLayer, Marker } from "react-leaflet";
import { useWildPlantsWithCoords } from "@/hooks/use-wild-plants-with-coords";
import { FitBoundsOnMount } from "@/components/FitBoundsOnMount";
import { PlantMapSheet } from "@/components/PlantMapSheet";
import { buildPlantPinIcon } from "@/lib/build-plant-pin-icon";
import { track } from "@/lib/track";
import type { WildPlantWithCoords } from "@/hooks/use-wild-plants-with-coords";

export default function MapPage() {
  const { plants, isLoading } = useWildPlantsWithCoords();
  const [selectedPin, setSelectedPin] = useState<WildPlantWithCoords | null>(null);

  // Track map_opened once after data loads (avoid double-fire on re-render)
  const [tracked, setTracked] = useState(false);
  useEffect(() => {
    if (!isLoading && !tracked) {
      track("map_opened", { pin_count: plants.length });
      setTracked(true);
    }
  }, [isLoading, tracked, plants.length]);

  if (isLoading) {
    return (
      <div className="h-[calc(100vh-5rem)] flex items-center justify-center bg-secondary/50">
        <span className="font-body text-muted-foreground">Cargando mapa…</span>
      </div>
    );
  }

  if (plants.length === 0) {
    // Edge case: usuario navegó directo a /mapa sin tener pins.
    // Tab no debería estar visible (D-07), pero deep link directo es posible.
    return (
      <div className="px-6 py-16 text-center">
        <h1 className="font-display text-2xl font-bold mb-2">
          Aún no tienes descubrimientos en el mapa
        </h1>
        <p className="font-body text-muted-foreground mb-6">
          Identifica una planta y márcala como descubrimiento para que aparezca aquí.
        </p>
        <a href="/" className="font-body underline">Identificar una planta</a>
      </div>
    );
  }

  return (
    // h-[calc(100vh-5rem)] = viewport - pb-20 del AppLayout
    // Importante: NO añadir LegalFooter aquí (lo añade AppLayout automáticamente,
    // pero el mapa lo cubre visualmente). En esta vista, dejarlo no molesta porque
    // el mapa absorbe touches sobre la zona del footer.
    <div className="h-[calc(100vh-5rem)] relative">
      <MapContainer
        center={[plants[0].lat, plants[0].lng]}  // placeholder; FitBoundsOnMount corrige
        zoom={13}
        style={{ height: "100%", width: "100%" }}
        // No StrictMode parent (verified). MapContainer props immutable.
      >
        <TileLayer
          url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png"
          attribution='&copy; <a href="https://www.openstreetmap.org/copyright" target="_blank" rel="noopener">OpenStreetMap</a> contributors'
        />
        {plants.map((p, index) => (
          <Marker
            key={p.id}
            position={[p.lat, p.lng]}
            icon={buildPlantPinIcon()}
            eventHandlers={{
              click: () => {
                track("map_pin_tapped", {
                  plant_search_id: p.id,
                  pin_index_among_total: index,
                });
                setSelectedPin(p);
              },
            }}
          />
        ))}
        <FitBoundsOnMount pins={plants} />
      </MapContainer>
      <PlantMapSheet
        plant={selectedPin}
        onClose={() => setSelectedPin(null)}
      />
    </div>
  );
}
```

**Importante para R4 acceptance:** El DOM contendrá `.leaflet-marker-icon` por cada pin. El test E2E debe esperar `await page.waitForSelector(".leaflet-marker-icon")` antes de assertar count.

**Performance check:** Con <20 pins típicos y hasta 200 heavy users (per SPEC.md § Constraints), `<Marker>` rendering directo es aceptable. Sin clustering en v0. Si en futuro algún usuario reporta lag con >200 pins, evaluar `react-leaflet-cluster`. [VERIFIED: SPEC.md § Constraints línea "Volume: <20 pins por usuario típico esperado"]

import { es } from "date-fns/locale/es";

  Sheet,
  SheetContent,

  SheetDescription,

            <img
              src={plant.imageUrl}
              alt={commonName}

            />

              <SheetTitle className="font-display text-2xl font-bold leading-tight">

              </SheetTitle>

                </p>
              )}

function splitNameField(name: string): { commonName: string; scientificName: string | null } {

## Common Pitfalls

### Pitfall 1: MapContainer sin altura → mapa en blanco

**What goes wrong:** El `<MapContainer>` renderiza un `<div>` pero el mapa interno queda con dimensiones 0×0 hasta el primer `map.invalidateSize()`.
**Why it happens:** Leaflet calcula tile loading basándose en `mapSize` del contenedor. Si el padre no tiene altura explícita (h-full sin padre con altura), `mapSize = (0,0)`.
**How to avoid:** Pasar `style={{ height: "100%", width: "100%" }}` al `MapContainer` Y asegurar que el padre tenga altura computada. En MapPage: `<div className="h-[calc(100vh-5rem)]">`.
**Warning signs:** Mapa muestra solo el control de atribución sobre fondo blanco. DevTools muestra `.leaflet-container { height: 0px }`.

### Pitfall 2: `import "leaflet/dist/leaflet.css"` después de leaflet → tile dimensions rotas

**What goes wrong:** Primera renderización del mapa muestra tiles en posiciones random porque las CSS rules de `.leaflet-tile` (position absolute + transform) no están aplicadas todavía.
**Why it happens:** Si `import L from "leaflet"` se ejecuta antes que el CSS module load, el render del MapContainer se anticipa al CSS apply.
**How to avoid:** Importar CSS en `src/main.tsx` **antes** de `./index.css` (que es lo último en `main.tsx` actual). El CSS de leaflet termina en `<style>` injected antes del primer mount de cualquier MapContainer.
**Warning signs:** Tiles aparecen "rotos" o solapados en primer mount, se arreglan al hacer pan o resize de ventana.

### Pitfall 3: divIcon HTML sin override de bg → cuadrado blanco con borde gris

**What goes wrong:** Leaflet aplica clase default `.leaflet-div-icon { background: white; border: 1px solid #666 }`. Tu HTML interno con bg cream queda envuelto en una caja blanca.
**Why it happens:** Leaflet defaults se diseñaron para los iconos default; cuando overrideas con divIcon, el outer wrapper conserva el style default.
**How to avoid:** Pasar `className: "plant-map-pin"` (no `''` ni omitir) y añadir CSS global `.plant-map-pin { background: transparent !important; border: none !important; }`. `!important` es necesario porque Leaflet aplica inline styles.
**Warning signs:** Pin se ve como sticker dentro de una caja blanca.

### Pitfall 4: Tap en pin abre sheet PERO sheet cierra al instante por click-outside

**What goes wrong:** El click en el pin se propaga al overlay del Sheet (que captura clicks fuera) → Sheet cierra antes de poder verlo.
**Why it happens:** Radix Dialog `Sheet` cierra en click sobre overlay. El click del pin viaja por bubble-up del DOM.
**How to avoid:** El `eventHandlers={click}` de Leaflet ya hace `e.originalEvent.stopPropagation()` internamente por defecto (CONFIRMAR — testear). Si no, añadir handler explícito: `click: (e) => { e.originalEvent.stopPropagation(); setSelectedPin(...); }`.
**Warning signs:** Tap en pin → flash del sheet por 100ms → desaparece.

### Pitfall 5: Tab "Mapa" no aparece tras clasificar la primera wild (AC2 falla)

**What goes wrong:** Usuario clasifica una planta como "wild" (con coords) en `/planta/:id`. Vuelve a `/` y la tab "Mapa" no está en el DOM hasta refresh manual.
**Why it happens:** `useContextCounts` no se invalida automáticamente tras un UPDATE — el patrón establecido es manual refetch (Phase 02.1 D-12).
**How to avoid:** Implementar opción (a) de § "Implementation guidance → R1": `useClassifyPlant` dispatcha CustomEvent `mp:context-changed`, BottomTabBar escucha y llama `refetch()` de useContextCounts.
**Warning signs:** Tab "Mapa" requiere reload del browser para aparecer.

### Pitfall 6: `pb-safe` del SheetContent no funciona en iOS Safari < 17

**What goes wrong:** Botones "Ver detalle" / "Cerrar" del Sheet quedan tapados por el home indicator del iPhone X+.
**Why it happens:** `env(safe-area-inset-bottom)` requiere `viewport-fit=cover` meta tag — ya está (verificado en `index.html` línea 5). En Safari ≥16 funciona, pero algunos modelos antiguos (iOS 15-) no soportan ciertas propiedades.
**How to avoid:** Usar `padding-bottom: max(1.5rem, env(safe-area-inset-bottom))` o utility `pb-safe` definido en tailwind config. Patrón ya en uso en BottomTabBar y CookieConsentBanner. Replicar en `PlantMapSheet`.
**Warning signs:** Usuario reporta que "el botón Cerrar está medio tapado abajo".

### Pitfall 7: OSM tiles bloqueadas por CSP o ad-blocker

**What goes wrong:** Tiles no cargan, mapa queda gris.
**Why it happens:** Algunas extensiones de browser (uBlock Origin con listas agresivas) o políticas corporate CSP bloquean `*.tile.openstreetmap.org`.
**How to avoid:** Documentar comportamiento (mapa gris + pins visibles) en SPEC.md ya hecho (AC12). No es bug — es entorno del usuario.
**Warning signs:** Mapa gris pero pins visibles. Network tab muestra tile requests con `(blocked:other)` o status 0.

### Pitfall 8: Bundle size explota por importar `leaflet/dist/leaflet-src.esm.js`

**What goes wrong:** Bundle final crece 200KB+ porque alguien importa el ESM debug build en lugar del producción.
**Why it happens:** `react-leaflet` importa correctamente la versión optimizada, pero si añades `import L from "leaflet/src/Leaflet"` o similar, traes el unminified source.
**How to avoid:** Solo `import L from "leaflet"` (resuelve a `leaflet/dist/leaflet-src.js` minified). Verificar con `npm run build` + check del bundle output.
**Warning signs:** `dist/` muestra leaflet-related chunks >100KB.

- **`react-leaflet@5.x` aquí no aplica.** Requiere React 19 — incompatible. No usar.

- **`L.tileLayer(...).addTo(map)` directo.** Idiom imperativo. Usar `<TileLayer>` componente.
