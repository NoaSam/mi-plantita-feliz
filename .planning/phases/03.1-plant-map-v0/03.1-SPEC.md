# Phase 03.1: Plant Map v0 — Specification

**Created:** 2026-05-16
**Ambiguity score:** 0.20 (gate: ≤ 0.20) ✓
**Requirements:** 8 locked

## Goal

Los usuarios con ≥1 planta clasificada como `wild` que tenga `lat/lng` no nulos pueden ver esas plantas como pins en un mapa accesible desde una pestaña condicional en `BottomTabBar`, y tocar un pin abre un preview con CTA al detalle completo de la planta.

## Background

**Lo que ya existe:**
- Columna `context` en `plant_searches` con valores `'home' | 'wild' | 'unclassified'` (migración `20260506000000`, Phase 02.1).
- Columnas `lat double precision` y `lng double precision` nullable en `plant_searches` (migración `20260409000000`).
- Edge function `identify-plant` ya popula `lat`/`lng` cuando el usuario concede permiso de geolocation al capturar.
- Hook `useGeolocation()` en `src/hooks/use-geolocation.ts` con soporte nativo (`@capacitor/geolocation`) y browser (`navigator.geolocation`).
- `BottomTabBar` (`src/components/BottomTabBar.tsx`) con 2-3 tabs hard-coded: Inicio, Mis plantas, (Ajustes si auth).
- Componente `ContextChip` (Phase 02.1) que renderiza chip 📍 wild en `/mis-plantas`.
- Ruta `/planta/:id` que monta `PlantResultView` por id (Phase 02.1).
- Bottom sheet pattern via shadcn `Sheet` ya usado en `AnonClassificationWall` (Phase 02.1).

**Lo que NO existe (gap que esta phase cierra):**
- Ninguna ruta `/mapa` ni componente que renderice un mapa.
- `BottomTabBar` no soporta tabs condicionales basados en context counts.
- No hay query que filtre `plant_searches` por `context = 'wild' AND lat IS NOT NULL AND lng IS NOT NULL`.
- No hay dependencia de `leaflet` ni `react-leaflet` en `package.json`.

**Trigger:** Phase 03.1 es la tercera pata del bundle vertical-slice (Foundations 02.1 + Calendar v0 [Phase 3] + Map v0 [Phase 03.1]). Las 3 se publican juntas en un único release para evitar "dead UI" entre fases. Sin Map v0, las plantas clasificadas como `wild` no tienen destino visible — el usuario clasifica sin saber para qué.

## Requirements

1. **Tab condicional "Mapa" en BottomTabBar**: La tab aparece automáticamente cuando el usuario logged-in tiene ≥1 planta con `context = 'wild' AND lat IS NOT NULL AND lng IS NOT NULL`.
   - Current: `BottomTabBar` tiene tabs hard-coded (Inicio, Mis plantas, Ajustes). No reactivo a context counts.
   - Target: `BottomTabBar` consume un hook de counts y renderiza la tab "Mapa" (icono `MapPin`, ruta `/mapa`) cuando `wild_with_coords_count >= 1`. Para `wild_with_coords_count == 0` o usuario anónimo, la tab no se renderiza.
   - Acceptance: Para un usuario test sin wild → la tab "Mapa" NO está en el DOM. Para el mismo usuario tras identificar 1 wild con coords → la tab "Mapa" SÍ está en el DOM (verificable por aria-label="Mapa" o data-testid). Para usuario anónimo con searches en localStorage → la tab "Mapa" NO está en el DOM.

2. **Ruta `/mapa` montada en `App.tsx`**: Existe una ruta `/mapa` registrada dentro de `<AppLayout>` que monta una nueva página `MapPage`.
   - Current: `App.tsx` no tiene ninguna ruta `/mapa`. Cualquier navegación a `/mapa` cae en `<NotFound />`.
   - Target: `App.tsx` líneas dentro del bloque `<Routes>` incluye `<Route path="/mapa" element={<AppLayout><MapPage /></AppLayout>} />`. `AppLayout` se preserva (header + BottomTabBar visibles).
   - Acceptance: Navegación directa a `/mapa` carga `MapPage` (no `NotFound`). El `BottomTabBar` sigue visible. El `<head>` document title se actualiza si la página lo setea.

3. **Hook `useWildPlantsWithCoords()` (o equivalente)**: Existe un hook que retorna las plantas wild con coordenadas del usuario actual.
   - Current: Ningún hook filtra `plant_searches` por context + coords. `usePlantHistory` retorna toda la historia sin filtros.
   - Target: Nuevo hook (nombre exacto a definir por planner) que ejecuta `SELECT id, common_name, scientific_name, image_url, lat, lng, created_at FROM plant_searches WHERE user_id = auth.uid() AND context = 'wild' AND lat IS NOT NULL AND lng IS NOT NULL ORDER BY created_at DESC`. Devuelve `{ data, isLoading, error }`.
   - Acceptance: El hook devuelve solo filas con `context = 'wild'` y `lat`/`lng` no nulos. Para usuario sin wild con coords retorna `data: []`. Test unitario con mock de Supabase client verifica el filtro WHERE.

4. **Render de pins en MapPage**: Cada planta retornada por el hook se renderiza como un pin en el mapa en `(lat, lng)` con un divIcon custom.
   - Current: No existe `MapPage`. Ningún componente renderiza pins.
   - Target: `MapPage` monta `<MapContainer>` de react-leaflet y renderiza un `<Marker>` por cada planta del hook usando un `L.divIcon` custom estilo sticker (esquinas redondeadas + sombra dura + icono hoja).
   - Acceptance: Para un usuario test con 3 wild plants con coords conocidas, el DOM del mapa contiene 3 elementos `.leaflet-marker-icon` con `transform: translate3d(...)` que mapea a las 3 lat/lng. Pin tamaño ~36×36px, visible sobre las tiles.

5. **Vista inicial: fit-bounds o setView según count**: Al montar `MapPage`, el mapa se centra/zoomea para mostrar todos los pins (o un solo pin con zoom city-level).
   - Current: N/A — no existe el mapa.
   - Target: Si `pins.length > 1` → `map.fitBounds(L.latLngBounds(allPinCoords), { padding: [40, 40] })`. Si `pins.length === 1` → `map.setView([pin.lat, pin.lng], 14)`. No persiste último centro/zoom.
   - Acceptance: Test con 3 pins muestra los 3 visibles en el viewport inicial. Test con 1 pin muestra el pin centrado con zoom z=14 (verificable por `map.getZoom()`).

6. **Tap pin → bottom sheet con preview**: Al tocar un pin, se abre un `Sheet` shadcn (side="bottom") con foto grande, nombre común, nombre científico, fecha del descubrimiento, y CTAs "Ver detalle" / "Cerrar".
   - Current: No existe ningún sheet para mapa.
   - Target: `MapPage` gestiona `useState<PlantSearch | null>(selectedPin)`. `Marker` tiene `eventHandlers={{ click: () => setSelectedPin(plant) }}`. Cuando `selectedPin !== null`, monta `<PlantMapSheet plant={selectedPin} onClose={() => setSelectedPin(null)} />` con `Sheet open={!!selectedPin}`.
   - Acceptance: Test E2E: tap pin → sheet visible (`role="dialog"` con `[data-side="bottom"]`). Sheet contiene `<img>` con `src` = `plant.image_url`, `<h2>` con `plant.common_name`, italic con `plant.scientific_name`, fecha formateada en español. Drag down o tap "Cerrar" cierra sheet.

7. **CTA "Ver detalle" navega a `/planta/:id`**: El botón primario del bottom sheet navega al detalle completo de la planta.
   - Current: N/A — no existe el sheet.
   - Target: Botón `<Button>Ver detalle</Button>` con `onClick={() => navigate(\`/planta/\${plant.id}\`)}`. La ruta `/planta/:id` ya existe (Phase 02.1).
   - Acceptance: Test E2E: tap "Ver detalle" en sheet → URL cambia a `/planta/{plant.id}` → la página renderiza `PlantResultView` con los datos de esa planta.

8. **Wild sin coords se omiten silenciosamente del mapa**: Plantas wild sin `lat/lng` no aparecen como pins ni como lista alternativa en `/mapa`.
   - Current: N/A — no existe el mapa.
   - Target: El hook de Requirement 3 filtra explícitamente `lat IS NOT NULL AND lng IS NOT NULL`. `MapPage` NO renderiza sección "Sin ubicación" ni banner contador de wild-sin-coords. Esas plantas siguen apareciendo en `/mis-plantas` con su `ContextChip` 📍 wild estándar.
   - Acceptance: Test con 2 wild (1 con coords, 1 sin coords) muestra exactamente 1 pin en el mapa. La planta sin coords NO aparece en ningún elemento del DOM de `MapPage`. En `/mis-plantas`, AMBAS plantas aparecen con su chip wild idéntico (sin diferenciador visual).

## Boundaries

**In scope:**
- Dependencia `leaflet` + `react-leaflet` añadida a `package.json`.
- CSS de `leaflet/dist/leaflet.css` importado en el bundle.
- Nueva página `src/pages/MapPage.tsx` (o `Map.tsx`) con ruta `/mapa`.
- Nuevo componente `src/components/PlantMapSheet.tsx` (bottom sheet con preview).
- Nuevo componente o helper para el pin custom (`PlantMapPin.tsx` o función que retorne `L.divIcon`).
- Nuevo hook para filtrar wild plants con coords (`use-wild-plants-with-coords.ts` o nombre equivalente).
- Modificación de `BottomTabBar.tsx` para soportar tabs condicionales basadas en counts.
- Nuevo hook agregador `useContextCounts()` o extensión de `use-unclassified-count.ts` con los 4 buckets.
- Modificación de `App.tsx` para registrar la ruta `/mapa`.
- Tile attribution de OSM (`© OpenStreetMap contributors`) renderizada por Leaflet vía `TileLayer` props.
- Empty state mínimo en `/mapa` si por edge case se llega sin pins (copy en español).
- Tests unitarios de los hooks nuevos.
- E2E Playwright happy path (`tests/e2e/map.spec.ts`).
- Sección "§ Phase 03.1" en `docs/posthog-events.md` con eventos `map_opened`, `map_pin_tapped`, `map_navigated_to_detail`.

**Out of scope:**
- **Clustering de pins** — Volume esperado <20 pins por usuario típico; clustering es over-engineering para v0. Defer a v1+ si emerge necesidad.
- **Filtros UI** (por especie, fecha, etc.) — Diferido a v1+ per `vertical-slice-release-strategy.md`.
- **Búsqueda por dirección/lugar** (geocoding) — Diferido a v1+.
- **Recordar último centro + zoom entre navegaciones** — Diferido a v1+ por simplicidad de v0.
- **Caching de tiles offline** — Diferido a v1+. Si offline, comportamiento aceptable: pins visibles sobre fondo gris.
- **Flujo retroactivo para añadir coords a una identificación pasada** — Descartado conscientemente; no actionable en mobile sin re-visitar el sitio.
- **Diferenciar visualmente wild-con-coords vs wild-sin-coords en `/mis-plantas`** — Descartado; data quality no accionable.
- **Banner "+N sin ubicación" en el mapa** — Descartado; dead UI sin acción posible.
- **Sketch dedicado del pin** — Decisión en CONTEXT.md: implementación directa con el design system existente.
- **Cambios en `BottomTabBar` para Phase 3 (Calendar v0 tab "Mi jardín")** — Esta phase prepara la infraestructura de tabs condicionales (vía `useContextCounts`), pero NO añade la tab "Mi jardín". Eso es trabajo de Phase 3.
- **Cambios en `useGeolocation`, en el edge function `identify-plant`, en `PhotoCapture`** — Estos ya capturan coords correctamente; no necesitan modificación.
- **Migración SQL nueva** — Las columnas `lat`, `lng`, `context` ya existen.
- **Push notifications de "X plantas en tu mapa"** — Out of scope per PROJECT.md.
- **Compartir descubrimiento (social)** — Out of scope per PROJECT.md.

## Constraints

- **Volume:** <20 pins por usuario típico esperado. Hasta ~200 pins puede ocurrir en heavy users; el render directo de react-leaflet debe seguir siendo aceptable hasta ese rango sin clustering.
- **Bundle size:** Adición ≤ ~60KB minified+gzipped (Leaflet ~40KB + react-leaflet wrapper ~15KB). Cualquier desviación significativa hacia arriba debe levantarse en code review.
- **Platform compat:** Debe funcionar en Capacitor Android WebView 8.x y en navegadores móviles modernos (iOS Safari 16+, Chrome Android). Sin polyfills exóticos.
- **Permisos:** El mapa NO solicita permiso de geolocation al abrir. Los pins usan coords ya almacenadas en `plant_searches` (capturadas al momento de identificación). Si el usuario denegó permisos en su día, simplemente no hay pins para él en el mapa (tab no aparece).
- **Tile provider:** OpenStreetMap (`https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`). Atribución obligatoria visible en el mapa per licencia ODbL.
- **Offline behavior:** Sin caching de tiles. Si offline: pins visibles sobre fondo gris (Leaflet default). Sin toast de error ni reintentos. Aceptable para v0.
- **Tests:** Hooks nuevos requieren tests unitarios (consensus del proyecto). E2E smoke con Playwright cubre el happy path. NO se requieren tests de UI de componentes per `CLAUDE.md`.
- **i18n:** Toda UI nueva en español (CLAUDE.md). Código en inglés (variables, comentarios, commits).
- **Auth:** Solo logged-in users ven la tab "Mapa". Usuarios anónimos no tienen `context` en sus searches.
- **Privacy:** Verificar que `src/pages/legal/PrivacyPolicy.tsx` menciona el uso del mapa con coords. Si no, añadir párrafo corto durante esta phase.

## Acceptance Criteria

- [ ] **AC1**: Para un usuario test sin wild con coords, la tab "Mapa" NO se renderiza en `BottomTabBar`.
- [ ] **AC2**: Tras identificar 1 wild con coords (manualmente o vía seed), la tab "Mapa" aparece en `BottomTabBar` sin reload manual (refetch automático o reactivo).
- [ ] **AC3**: Para usuario anónimo (sin sesión), la tab "Mapa" NO se renderiza nunca, aunque tenga searches en localStorage.
- [ ] **AC4**: Navegación a `/mapa` carga `MapPage` (no `NotFound`); `BottomTabBar` visible.
- [ ] **AC5**: Para un usuario con N wild plants con coords, el DOM del mapa contiene exactamente N `.leaflet-marker-icon` elements; las plantas wild sin coords NO aparecen.
- [ ] **AC6**: Con N>1 pins, el viewport inicial muestra todos los pins (verificable: cada `latLng` está dentro de `map.getBounds()`). Con N=1, `map.getZoom() === 14`.
- [ ] **AC7**: Tap en pin → bottom sheet visible (`role="dialog"`) con `<img>` (src=image_url), nombre común, nombre científico (italic), fecha formateada en español (date-fns + locale `es`).
- [ ] **AC8**: Tap "Ver detalle" en bottom sheet → URL cambia a `/planta/{id}` y `PlantResultView` renderiza con datos de esa planta.
- [ ] **AC9**: E2E Playwright (`tests/e2e/map.spec.ts`): happy path full (identificar wild → tab aparece → tap → ver pin → tap pin → sheet → "Ver detalle" → `/planta/:id`) pasa verde en CI.
- [ ] **AC10**: Hook unit test verifica que el filtro WHERE incluye `context = 'wild' AND lat IS NOT NULL AND lng IS NOT NULL`.
- [ ] **AC11**: Atribución OSM (`© OpenStreetMap contributors`) visible en el mapa como link.
- [ ] **AC12**: Si tiles fallan al cargar (simular con DevTools throttling offline), la app no crashea; pins quedan visibles sobre fondo gris; sin toast de error.
