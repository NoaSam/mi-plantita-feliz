## Stack del mapa (librería + tiles)

| Option | Description | Selected |
|--------|-------------|----------|
| Leaflet + OpenStreetMap (Recommended) | Bundle ~40KB, gratis para siempre, sin API key, atribución simple en una línea. Render raster (no vector) bastante para v0. Battle-tested en móvil. Si v1 necesitamos vector/clústers, migrar a MapLibre es trivial. | ✓ |
| MapLibre GL + tiles gratis | Vector tiles (mejor zoom y render), bundle ~200KB. Tiles gratis vía demo.maptiler.com (limitado) o requiere registrarse en MapTiler/Stadia. Buena estética pero más setup. | |
| Mapbox GL | Máxima calidad visual, estética customizable (matches sticker design system). Token requerido, free tier 50k MAU pero monitorear coste. Bundle ~250KB. | |

**User's choice:** Leaflet + OSM.
**Notes:** Sin paid tier por ahora; v0 simple. Si en v1+ se necesita vector/clústers, migración a MapLibre es factible.

## Entry point + coexistencia con Calendar v0

Pregunta inicial fue "¿Dónde vive el mapa?" — la usuaria pidió aclaración sobre cómo conviven Calendar y Mapa para usuarios que tienen ambos modos. Se reformuló la pregunta como decisión cross-fase (afecta también a Phase 3).

| Option | Description | Selected |
|--------|-------------|----------|
| Pestañas condicionales en BottomTabBar (Recommended) | Tabs "Mi jardín" y "Mapa" aparecen/desaparecen según haya >=1 planta de ese tipo. Para usuario con ambos: Inicio · Mi jardín · Mapa · Mis plantas · (Ajustes) = 4-5 tabs. Usuario nuevo: 2 tabs. Cada modo tiene su ruta dedicada (/jardin, /mapa). Máxima discoverability + simetría. | ✓ |
| Ambos como secciones en Home | Inicio se vuelve dashboard: PhotoCapture + UnclassifiedSection + "Mi jardín" (mini-lista) + "Tus descubrimientos" (mini-mapa o card). BottomTabBar queda en 2-3 tabs. Sin rutas dedicadas: todo en /. Pro: simple. Contra: home denso, mini-mapa raro en home. | |
| Híbrido: previews en Home + páginas full vía "Ver todo" | Home muestra cards/previews compactos de cada modo. Tap → ruta dedicada (/jardin, /mapa) full-screen. BottomTabBar minimalista (2-3 tabs). Pro: profundidad bajo demanda. Contra: 2 taps para llegar al detalle. | |
| Hub dentro de /mis-plantas con sub-tabs | /mis-plantas se vuelve hub con tabs internas: "Todas | Mi jardín | Descubrimientos". Mi jardín = lista con riego. Descubrimientos = mapa. BottomTabBar queda en Inicio · Mis plantas · Ajustes. Pro: máxima coherencia ("todo lo mío en un sitio"). Contra: la página History acumula 3 modos visuales muy distintos. | |

**User's choice:** Tabs condicionales en BottomTabBar.
**Notes:** Decisión cross-fase: se propaga a Phase 3 (Calendar v0). Tab "Mi jardín" aparecerá cuando `home_count >= 1`. Tab "Mapa" cuando `wild_with_coords_count >= 1`. Rutas dedicadas `/jardin` y `/mapa`.

## Pin interaction — tap

| Option | Description | Selected |
|--------|-------------|----------|
| Bottom sheet con preview rico + CTA (Recommended) | Tap pin → sheet shadcn desde abajo con foto grande + nombre común + nombre científico + fecha + botón "Ver detalle completo" (→ /planta/:id). Coherente con AnonClassificationWall, deja el mapa visible. Más superficie táctil que un popup. | ✓ |
| Popup inline de Leaflet | Tap pin → popup pequeño flotante encima del pin con foto thumb + nombre + fecha + link "Ver detalle". Patrón nativo de Leaflet. Más compacto pero menos hookable al design system sticker. | |
| Navegar directo a /planta/:id (sin preview) | Tap pin → navigate inmediato al detalle de la planta. Máximo simple, mínimo código. Contra: si el usuario tapó por error o quiere comparar pins, requiere back y re-explorar el mapa. | |

**User's choice:** Bottom sheet con preview rico + CTA.
**Notes:** Coherente con el patrón `AnonClassificationWall` ya implementado en 02.1.

## Wild sin coordenadas

Pregunta inicial planteó 3 opciones (lista, omitir, banner). La usuaria aclaró que las wild sin coords no pueden recuperar location retroactivamente (no hay flujo en la app), por lo que mostrarlas en el mapa es dead UI. Decisión locked: omitir silenciosamente del mapa.

| Option | Description | Selected |
|--------|-------------|----------|
| Lista "Sin ubicación" debajo del mapa (Recommended originally) | El mapa muestra solo las wild con coords. Debajo, sección colapsable con thumbnails. Tap → /planta/:id. Pro: nada se pierde, transparencia con el usuario. | |
| Se omiten del mapa silenciosamente | Las wild sin coords solo aparecen en /mis-plantas (History) con su chip. No se mencionan en el mapa. Pro: pantalla limpia. Contra: usuario puede pensar "¿dónde están mis otras plantas?". | ✓ |
| Banner discreto en el mapa: "+ N sin ubicación" | Mapa con pins + chip flotante arriba/abajo "+3 sin ubicación" que al tocar abre bottom sheet con la lista. Compromise: visible pero no roba protagonismo. | |

**User's choice:** Omitir silenciosamente (después de aclaración).
**Notes:** Razonamiento clave de la usuaria: "si deniega [permiso] nunca tendremos esa información, por tanto no tiene sentido mostrarlo en mapa una vez se registre… nunca podrá recolocarlas". La condición para mostrar la tab "Mapa" es `wild_with_coords_count >= 1` (no `wild_count`), por lo que un usuario sin ninguna wild plotteable nunca ve la tab → nunca llega al mapa → nunca vive el caso "vacío sospechoso".

## Vista inicial del mapa

| Option | Description | Selected |
|--------|-------------|----------|
| Fit-bounds a todos los pins con padding (Recommended) | Zoom y centro automáticos para que todos los pins entren con margen. Para 1 solo pin: zoom city-level (z=14). Pro: el usuario ve toda su colección de un vistazo sin pedir permiso de location ni hacer scroll. Código: ~5 líneas con map.fitBounds(). | ✓ |
| Centrado en mi ubicación actual | Reusa permiso de location (ya concedido si tiene >=1 wild con coords). Zoom medio (z=13). Pro: útil si estás caminando y quieres ver lo cercano. Contra: pins lejanos no se ven hasta hacer zoom out; requiere lectura GPS al abrir (latencia). | |
| Centrado en el último descubrimiento (más reciente) | Centra en el pin con created_at más reciente, zoom moderado. Pro: contextual a la actividad reciente. Contra: pins en otra ciudad/región quedan fuera del viewport inicial. | |

**User's choice:** Fit-bounds.
**Notes:** Edge case (1 solo pin) bifurca a `setView` con z=14 (city level). No persiste último centro/zoom (diferido a v1+).
