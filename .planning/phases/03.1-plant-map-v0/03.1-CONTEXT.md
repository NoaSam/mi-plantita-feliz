# Phase 03.1: Plant Map v0 — Context

**Gathered:** 2026-05-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Pantalla de mapa (`/mapa`) que muestra los `plant_searches` con `context = 'wild'` y `lat/lng` no nulos como pins sobre tiles de OpenStreetMap. Tap en pin → bottom sheet con preview de la planta + CTA al detalle. Entry point: pestaña condicional en `BottomTabBar` que aparece cuando `wild_with_coords_count >= 1`. Empty state cuando aún no hay descubrimientos plotteables.

Plantas wild **sin** `lat/lng` (usuario denegó permiso de location o falló la lectura GPS) se omiten silenciosamente del mapa — siguen visibles en `/mis-plantas` con su `ContextChip` 📍 wild. Sin clustering, sin filtros, sin búsqueda, sin búsqueda de direcciones, sin notificaciones, sin recordar última vista al volver. Esos quedan diferidos a v1+.

Forma parte del bundle vertical-slice (Foundations 02.1 + Calendar v0 [3] + Map v0 [03.1]); las 3 fases se publican juntas en un único release. NO entrega Calendar v0 (Phase 3) ni modifica Foundations (02.1).

**Decisión cross-fase capturada aquí (aplicable también a Phase 3):** el patrón "pestaña condicional en BottomTabBar" se replica para `/jardin` (Calendar v0). La tab "Mi jardín" aparece cuando `home_count >= 1`. Esta decisión se persistirá también al hacer `/gsd-discuss-phase 3`.

</domain>

<decisions>
## Implementation Decisions

### Stack del mapa (librería + tiles)

- **D-01:** **Leaflet + OpenStreetMap raster tiles.** Bundle ~40KB, gratis para siempre, sin API key, atribución de OSM en una línea. Render raster suficiente para v0 (sin clusters, sin pesos visuales complejos). Patrón battle-tested en mobile WebView. Si v1+ pide vector tiles o clustering, migrar a MapLibre GL es factible sin reescribir el modelo de datos.
- **D-02:** Usar `react-leaflet` como wrapper React idiomático (no Leaflet raw). Patrón estándar del ecosistema y consistente con la convención del proyecto de usar wrappers React (shadcn, framer-motion). El planner debe verificar la versión compatible con React 18.3.
- **D-03:** Tile URL canónica: `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`. Atribución obligatoria de OSM al pie del mapa (ya un `<a>` link inline a `https://www.openstreetmap.org/copyright`). Cumple licencia ODbL.

### Entry point + navegación (cross-fase: aplica también a Phase 3)

- **D-04:** **Pestañas condicionales en `BottomTabBar`.** Para Phase 03.1: nueva tab **"Mapa"** (icono `MapPin` de lucide-react) que aparece sólo cuando el usuario tiene `wild_with_coords_count >= 1`. Para Phase 3 (Calendar v0): nueva tab **"Mi jardín"** (icono a decidir, sugerencia `Leaf`/`Sprout`) que aparece cuando `home_count >= 1`. Tab order propuesto: **Inicio · Mi jardín · Mapa · Mis plantas · Ajustes** — las 2 nuevas se intercalan entre "Inicio" y "Mis plantas".
- **D-05:** Ruta dedicada **`/mapa`** registrada en `src/App.tsx` dentro de `<AppLayout>` (mantiene `BottomTabBar` visible). La página monta el mapa Leaflet a pantalla completa (descontando header + bottom tab bar). Phase 3 hará lo mismo con `/jardin`.
- **D-06:** Tabs condicionales requieren un counter hook nuevo `useContextCounts()` que devuelva `{ home: number, wild_with_coords: number, wild_without_coords: number, unclassified: number }`. Reutilizable por `BottomTabBar`, `UnclassifiedSection`, `HistorySummary`, y los empty states. **El planner debe decidir si extender `useUnclassifiedCount` o crear un hook nuevo agregador** — el segundo es más DRY a futuro.
- **D-07:** Para usuario anónimo: las tabs nuevas **nunca aparecen** porque sus datos están en localStorage y nunca tienen `context` clasificado (la clasificación requiere login per SPEC 02.1). La condición `wild_with_coords_count >= 1` es lógicamente falsa para `!user`.

### Pin interaction (tap + visual)

- **D-08:** Tap en pin → **bottom sheet** de shadcn (`Sheet` con `side="bottom"`). Contenido: foto grande (full-width del sheet, aspect-square o 4:3), nombre común grande (font display Fraunces), nombre científico en cursiva debajo, fecha del descubrimiento (`date-fns` formato "5 de marzo de 2026"), botón primario "Ver detalle completo" → `navigate(\`/planta/${id}\`)`, botón secundario "Cerrar". Coherente con el patrón de `AnonClassificationWall` (sketch 003D) y deja el mapa visible al cerrar.
- **D-09:** Pin custom **sticker style** vía `L.divIcon({ html: '...', className: '...' })`. HTML inline: `<div>` con `border-radius: 1rem`, `box-shadow: 4px 4px 0 var(--olive-dark)`, fondo `cream` y un icono de hoja (`Leaf` de lucide-react serializado a SVG inline, o un emoji 🌿 como fallback simple). Tamaño ~36×36px. Coherente con el design system del proyecto (sticker / neo-brutalist suave). El planner valida si lucide-react renderiza bien dentro de `divIcon` o si usar emoji es más simple.
- **D-10:** Hover/active state del pin: leve scale-up (`transform: scale(1.1)`) en `:active` para feedback táctil. Sin animación de entrada compleja en v0 — los pins aparecen estáticos al cargar.

### Wild sin coordenadas

- **D-11:** Las plantas wild sin `lat/lng` (porque el usuario denegó permiso de location o el GPS falló al capturar) **se omiten silenciosamente** del mapa. NO se muestra sección "Sin ubicación" debajo del mapa ni banner flotante con el conteo. Razón: la app no tiene flujo retroactivo para añadir coords a una identificación pasada (`useGeolocation` solo lee en `PhotoCapture` al momento de capturar; no se re-pregunta permiso), por lo que mostrar una lista de plantas "no plotteables" en el mapa es dead UI — el usuario no puede actuar sobre ellas.
- **D-12:** Estas wild sin coords siguen apareciendo en `/mis-plantas` (History) con su `ContextChip` 📍 wild estándar, igual que las que sí tienen coords. **No se diferencian visualmente** entre wild-con-coords y wild-sin-coords en ningún lado — esa distinción de data quality no es accionable para el usuario, así que no se surfacea.
- **D-13:** La tab "Mapa" usa `wild_with_coords_count` (no `wild_count`), por lo que si todas las wild del usuario fueran sin coords, la tab simplemente no aparecería — el usuario nunca llega a una pantalla "vacía sospechosa".

### Vista inicial del mapa

- **D-14:** Al montar `<MapPage>`: `map.fitBounds(L.latLngBounds(allPinCoords), { padding: [40, 40] })`. Esto asegura que todos los pins entren en el viewport con margen visual. Sin lectura de geolocation al abrir (evita latencia GPS y permiso adicional).
- **D-15:** Caso especial **1 solo pin**: `fitBounds` colapsa a un punto sin zoom razonable. Usar `map.setView([pin.lat, pin.lng], 14)` para forzar zoom city-level (z=14 ≈ barrio visible). El planner debe detectar `allPinCoords.length === 1` y bifurcar.
- **D-16:** Vista al volver a la pantalla: la misma lógica `fitBounds`/`setView` se re-ejecuta al montar — **no se persiste último centro/zoom** (diferido a v1+). Razón: simplifica el v0 y evita estado en localStorage que puede stale.
- **D-17:** Min/max zoom de Leaflet: defaults (z=0 a z=18). No restringir — el usuario puede hacer zoom out al planeta o zoom in al edificio si quiere.

### Claude's Discretion

- **Empty state copy** cuando el usuario tiene `wild_count == 0` Y no tiene la tab "Mapa" visible: caso irrelevante porque no se llega a la página. Si por bug el usuario navega directo a `/mapa` con cero pins, mostrar empty state simple: "Aún no tienes descubrimientos en el mapa. Identifica una planta y márcala como descubrimiento para que aparezca aquí." con CTA a `/`.
- **Eventos PostHog**: el researcher/planner debe definir el contrato siguiendo el patrón de Phase 02.1 (`docs/posthog-events.md`). Eventos esperados: `map_opened` (props: `pin_count`), `map_pin_tapped` (props: `plant_search_id`, `pin_index_among_total`), `map_navigated_to_detail` (props: `plant_search_id`, `from: 'pin_sheet'`). Añadir sección "§ Phase 03.1" al doc.
- **Loading state**: skeleton del contenedor del mapa mientras se cargan las tiles. Sin spinner global porque las tiles cargan progresivamente. Implementación trivial — el planner decide.
- **Offline behavior**: si las tiles de OSM no cargan (offline), Leaflet muestra el viewport gris con los pins visibles. Aceptable para v0. Sin caching de tiles a `IndexedDB` (eso es v1+).
- **Tile attribution copy** (footer del mapa): `© OpenStreetMap contributors` como link a `https://www.openstreetmap.org/copyright`. Sin negociación — es licencia.
- **Iconos del BottomTabBar nuevos**: `MapPin` (lucide-react, ya usado en `LocationConsentModal`) para Mapa. Para Mi jardín (Phase 3): sugerir `Sprout` o `Leaf` cuando se discuta Phase 3.
- **Privacy policy update**: si el equipo de legal-compliance ya cubrió "el mapa mostrará tus descubrimientos" en `PrivacyPolicy.tsx`, no tocar. Si no, añadir un párrafo corto. El planner debe verificar `src/pages/legal/PrivacyPolicy.tsx`.
- **Tests**: hook `useContextCounts` debe tener tests unitarios (consensus del proyecto: tests para hooks de lógica de negocio). La página `MapPage` puede tener un test smoke E2E (Playwright ya está disponible per `package.json`).

</decisions>

<deferred>
## Deferred Ideas

Las siguientes ideas surgieron en discusión o están en `vertical-slice-release-strategy.md` § "Qué se difiere a v1+". Capturadas para no perderlas:

- **Clustering de pins** — cuando un usuario tenga muchos descubrimientos en la misma zona. Requiere `leaflet.markercluster` o migrar a MapLibre. Reevaluar cuando alguien tenga >20 pins en un city block.
- **Filtros por especie / fecha / categoría** — UI extra de filtrado. Diferido a v1+.
- **Búsqueda por dirección o lugar** — geocoding (Nominatim API gratis). Diferido a v1+.
- **Recordar última vista (centro + zoom)** — persistir en localStorage. Útil cuando el usuario navega entre `/mapa` y `/planta/:id` y vuelve. Simple de añadir post-v0.
- **Caching de tiles offline** — `leaflet-offline` o IndexedDB. Diferido a v1+ (requiere validar uso real).
- **Vista de detalle rica desde el pin** — el bottom sheet actual es minimalista; v1+ podría incluir más datos (cuidados breves, "compartir descubrimiento", etc.).
- **Flujo retroactivo para añadir coords a una planta ya identificada** — descartado consciently en discussion (no actionable para el usuario en mobile sin re-visitar el sitio). Si en v2+ se quiere "geotagear" desde galería con EXIF, abrir nuevo seed.
- **Diferenciar visualmente wild-con-coords vs wild-sin-coords en `/mis-plantas`** — descartado consciently (data quality no accionable, ruido visual).
- **Mostrar contador "+N sin ubicación" en el mapa** — descartado conscientemente (dead UI sin acción posible).
- **Sketch dedicado para el pin custom** — opción rechazada; se acepta implementación directa siguiendo el design system existente. Si el resultado no convence post-implementation, sketchear post-launch.
- **Empty state ilustrado** — v0 usa empty state texto-only. v1+ podría tener ilustración custom.
- **Compartir descubrimiento** (social) — fuera de scope (PROJECT.md § Out of Scope).
- **Notificaciones push de "X plantas en tu mapa"** — fuera de scope (PROJECT.md § Out of Scope).
- **Pin click → zoom-to-pin animation** (en lugar de bottom sheet) — alternativa rechazada en favor del bottom sheet.

</deferred>
