**4-bucket Supabase aggregation hook with reactive refetch via CustomEvent — source of truth for plant-map tab visibility**

## Accomplishments

- Covers SPEC-AC2: hook listens for `mp:pending-classification-resolved` CustomEvent and refetches automatically (Pattern S4)

- `src/hooks/use-context-counts.test.ts` — 8 tests unitarios con chainable Supabase mock y modulo-based round tracking

## Decisions Made

- **Hook nuevo vs extender useUnclassifiedCount:** Hook NUEVO per RESEARCH.md Open Question 2 — más DRY a futuro y separa concerns (useUnclassifiedCount también devuelve thumbnails, concerns distintos)
- **4 queries paralelas vs select+aggregate:** head:true con count:exact es más eficiente (solo header Content-Range, sin transfer de filas)
- **Test mock fix:** El mock original del plan usaba condición `queryCounter === N` que solo funcionaba para el initial load. Se corrigió a modulo `((queryCounter-1) % 4)+1` para que refetch rounds (queries 5-8) mapeen a los mismos buckets

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Mock de test no soportaba múltiples rounds de refetch**
- **Found during:** Task 2 (ejecución de tests)
- **Issue:** El plan especificaba mock con `if (queryCounter === 1/2/3)` — las queries 5-8 del refetch caían todas en `makeChain(unclassifiedResult)` causando que `wild_with_coords` nunca se actualizara
- **Fix:** Cambiar a `((queryCounter - 1) % 4) + 1` para soportar N rounds de queries
- **Files modified:** src/hooks/use-context-counts.test.ts
- **Verification:** `npm test -- --run src/hooks/use-context-counts.test.ts` — 8/8 passed
