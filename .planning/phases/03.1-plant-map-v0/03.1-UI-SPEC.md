### Spacing rules for new surfaces (locked)

- **`MapPage` container:** full-bleed within the existing `max-w-md` (448px) `AppLayout` shell. The `<MapContainer>` element gets `style={{ height: "calc(100dvh - 4rem - env(safe-area-inset-bottom) - env(safe-area-inset-top))", width: "100%" }}`. `100dvh` is mandatory (NOT `100vh`) so iOS Safari's collapsing address bar does not crop the map. `4rem` = the `h-16` of `BottomTabBar`. Top safe-area is subtracted defensively for iOS PWA standalone notch even though `AppLayout` does not currently render a header on `/mapa` (the page is full-bleed).
- **`MapPage` page-level paddings:** **zero**. The map fills its container. No `px-` or `py-` on the page wrapper. Container of `AppLayout` (`max-w-md mx-auto pb-20 mb-safe`) is **overridden for `/mapa` only** — see "Page-level override" note below.
- **Pin marker size:** 36×36px square (per CONTEXT.md D-09 + SPEC.md AC5). Border `2px`. Inner content (emoji or icon) is `text-xl` ≈ 20px so the leaf glyph is well-padded inside the 36px box.
- **Pin tap-target:** Leaflet `Marker` element has an implicit ~8px event-bubble margin around the icon (via `iconSize` vs underlying div); combined with the visual 36px → effective tap area is ~44×44px which meets iOS HIG / Material minimum. **Documented exception** to the design-system default of ≥44px visual targets; this is acceptable because the pin is an icon-only affordance with high spatial distinctness (no neighbors to mis-tap unless pins overlap, which is deferred to clustering in v1+).
- **`PlantMapSheet` padding:** `p-6` (24px) inside the `SheetContent` — matches `AnonClassificationWall` exactly.
- **`PlantMapSheet` footer button stack gap:** `gap-2` (8px) — matches `AnonClassificationWall`.
- **`PlantMapSheet` max-height:** `max-h-[75dvh]` so the user always sees ≥25% of the map behind the sheet (preserves spatial context). Sheet content scrolls internally if it overflows — should never happen in v0 given the lean content, but documented for safety.
- **`MapEmptyState` outer padding:** `px-6 py-12` — vertical breathing room when section is shown standalone.
- **Tab "Mapa" in `BottomTabBar`:** inherits existing `py-2 px-4` per-tab padding from current `BottomTabBar.tsx` (line 33). No spacing change to the tab bar itself.

### Touch targets

- **Pin marker:** 36px visual + ~8px event bubble ≈ 44px effective. Marked exception above. ✓
- **Sheet primary CTA "Ver detalle":** shadcn `Button` `size="default"` height = 44px (h-11). ✓
- **Sheet secondary CTA "Cerrar":** shadcn `Button` `size="default"` height = 44px (h-11). ✓
- **Empty state CTA "Identificar una planta":** shadcn `Button` `size="default"` height = 44px (h-11). ✓
- **Tab "Mapa" button:** existing pattern in `BottomTabBar` — entire 64px tall area is the hit target. ✓
- **Leaflet attribution link** (`© OpenStreetMap contributors`): Leaflet renders this at ~11px font in the bottom-right corner of the map. This link is intentionally small (a legal requirement, not a primary CTA) and **does not need to meet the 44px target** because it is informational/legal microcopy. Documented exception.

### Exceptions (summary)

1. **Pin visual 36px** — effective tap area ~44px via Leaflet event bubble. (See above.)
2. **OSM attribution link ~11px** — informational/legal copy, not a primary CTA. Leaflet-controlled, not customized.
3. **Page-level override for `/mapa`:** The default `AppLayout` wrapper applies `max-w-md mx-auto pb-20 mb-safe` to the children container. For `/mapa` the inner content needs full-bleed (no horizontal padding, no `pb-20`). **The executor must EITHER conditionally drop these wrappers when `pathname === '/mapa'` in `AppLayout`, OR `MapPage` renders into its own `<div className="fixed inset-0 top-0 max-w-md mx-auto pointer-events-none">` overlay above `AppLayout`'s constrained content.** Locked recommendation: extend `AppLayout` with a `fullBleed?: boolean` prop that drops `pb-20 mb-safe` and `px-` constraints when true; `MapPage` opts in via wrapping itself in a sibling `<Route>` that passes the flag, OR `AppLayout` reads `useLocation().pathname` and switches off the inner wrapper for `/mapa`. **Planner picks one of these two patterns; both are acceptable. The MUST-HAVE is: the map fills viewport between top edge (or safe-area-top) and the fixed `BottomTabBar` top edge.**

### Accent reserved-for list (explicit, for this phase: empty)

The coral accent `--accent` is used in **zero** elements in this phase. Justification:

1. The map page is monotonal-by-design: cream background + verde oliva pin + neutral OSM tiles.
2. Pin doesn't need accent because there is only one pin variant (all pins are wild discoveries; no "danger" pin or "selected" pin in v0).

4. Empty state doesn't need accent because the CTA ("Identificar una planta") is an inviting forward action, not a warning — primary green is correct.

**If, post-launch, a v1+ feature introduces pin variants** (e.g., recently-added pin pulsing in coral; or a "currently-selected" highlighted pin), the accent reservation would update.

### 1. `MapPage.tsx` (new, `src/pages/MapPage.tsx`)

**Purpose:** Top-level page mounted at `/mapa`. Orchestrates the map container, pin rendering, sheet state, fit-bounds-on-mount, tracking, and empty state branch.

**Page-level structure (locked):**

```tsx
// Pseudo-structure — executor implements verbatim
export default function MapPage() {
  const { user } = useAuth();
  const { plants, isLoading } = useWildPlantsWithCoords();
  const [selectedPin, setSelectedPin] = useState<WildPlantWithCoords | null>(null);

  // Set document title on mount
  useEffect(() => { document.title = "Mapa de descubrimientos · Mi Plantita Feliz"; }, []);

  // Track map_opened with pin_count
  useEffect(() => {
    if (isLoading) return;
    track("map_opened", { pin_count: plants.length });
  }, [isLoading, plants.length]);

  if (!isLoading && plants.length === 0) {
    return <MapEmptyState />;
  }

  return (
    <div
      className="relative w-full"
      style={{
        height: "calc(100dvh - 4rem - env(safe-area-inset-bottom) - env(safe-area-inset-top))",
      }}
    >
      <MapContainer
        center={[40.4168, -3.7038] /* Madrid placeholder; FitBoundsOnMount overrides */}
        zoom={6}
        scrollWheelZoom={true}
        style={{ height: "100%", width: "100%" }}
        attributionControl={true}
      >
        <TileLayer
          url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png"
          attribution='&copy; <a href="https://www.openstreetmap.org/copyright" target="_blank" rel="noopener noreferrer">OpenStreetMap</a> contributors'
        />
        {plants.map((p, idx) => (
          <Marker
            key={p.id}
            position={[p.lat, p.lng]}
            icon={buildPlantPinIcon()}
            eventHandlers={{
              click: () => {
                setSelectedPin(p);
                track("map_pin_tapped", {
                  plant_search_id: p.id,
                  pin_index_among_total: idx + 1,
                  total_pins: plants.length,
                });

          />

      </MapContainer>
      <PlantMapSheet
        plant={selectedPin}
        onClose={() => setSelectedPin(null)}
      />
    </div>
  );
}
```

- `<Marker title="...">` prop in react-leaflet sets the underlying element's `title` attribute → screen-reader announces on focus.
- Pin emoji is decorative; the marker's `title` carries the semantic content. Acceptable per WCAG.

## Accessibility contract

- **Color contrast:** Foreground/background AAA confirmed; primary AAA; muted AAA. Pin border + OSM tile: high contrast on all tile categories.
- **Focus order on `MapPage`:** Map container (Leaflet-managed; arrow keys pan, +/- zoom) → first focusable Marker → next Marker → ... → attribution link. When sheet is open: focus traps inside sheet (Radix).
- **Focus order on `MapEmptyState`:** Title (heading, skip) → body (skip) → "Identificar una planta" CTA.
- **Focus order on `BottomTabBar`:** Tab 1 → Tab 2 → (Mapa if present) → Tab 3 → Tab 4. Unchanged.
- **Live regions:** None added by this phase. The map is not a live-updating surface (pins don't appear mid-session; they require navigation to home and back).
- **Reduced motion:** see Motion table.
- **Keyboard-only flow validation:** A user can: Tab to "Mapa" tab → Enter → arrow-pan map → Tab to first pin → Enter → focus moves to sheet "Ver detalle" → Enter → navigate to `/planta/:id`. Esc closes the sheet at any time.
- **Screen-reader copy:** Emoji 🌿 in pin is decorative; `Marker title` carries semantic content. Emoji 🗺️ in empty state is `aria-hidden`. Sheet title + description are wired via Radix automatically. Tab labels are explicit `aria-label`s.
- **Touch targets:** Pin effective ~44px (documented exception); CTAs 44px (h-11); tab buttons 64px (h-16). All compliant.
- **iOS PWA standalone:** safe-area insets respected on all 3 surfaces (`BottomTabBar` via `pb-safe`, `PlantMapSheet` via `pb-[max(1.5rem,env(safe-area-inset-bottom))]`, `MapPage` via `100dvh - 4rem - env(safe-area-inset-bottom) - env(safe-area-inset-top)`).
- **Android Capacitor WebView 8.3:** No platform-specific a11y blockers identified. WebView 8.x respects `aria-*` attributes and `role="button"` natively.

## FLAG-level (non-blocking) notes for downstream consumers

1. **Pin emoji rendering OS-dependence** — Android Noto and iOS Apple Color Emoji render 🌿 with slightly different proportions. Both are clearly "leaf"; no fallback needed. If post-launch visual review demands pixel-perfect cross-platform consistency, switch to lucide `Leaf` SVG inline (cost: minor React `renderToStaticMarkup` overhead per pin; trivial at <200 pins).
2. **Sheet drag-to-close NOT supported** — locked per CONTEXT.md D-08 (shadcn `Sheet`). Users have 3 close affordances: "Cerrar" button, tap-on-overlay, Esc. iOS PWA users may expect drag-down based on platform conventions; monitor post-launch for confusion. If material, switch to `vaul@0.9.9` in v1+ (already installed but unused; would require re-discuss of CONTEXT.md D-08).
3. **Tab "Mapa" mount has no animation** — pops into bar on `useContextCounts` refetch. Defer fade-in to v1+ unless visual review demands.
4. **`MapEmptyState` conflates "no data" with "Supabase query error"** — both render same empty state. Acceptable for v0; add distinct error copy in v1+ if observed.
5. **`UnclassifiedSection`-style item-removal motion for pins** — pins do not animate in/out when data changes. v0 acceptable; defer to v1+ if visual review demands.
6. **Leaflet default zoom buttons hidden** — touch pinch is the only zoom affordance. **FLAG:** Accessibility concern for users with motor impairments who can't pinch. **Mitigation:** Leaflet's keyboard zoom (`+`/`-` keys) remains active. If a11y audit demands visible zoom buttons, re-enable via `.leaflet-control-zoom { display: flex; }` and re-style to match design system.
7. **`viewport-fit=cover` + `user-scalable=no`** in `index.html` — verify and add if missing (planner task). This is a project-wide baseline fix, not phase-scoped, but the map phase is the most acute case.
8. **Optional attribution control restyling** — CSS commented in `index.css` snippet above. Planner/executor applies if visual review finds default Leaflet attribution jarring against the cream design system. Both states (default vs restyled) are AA-contrast compliant.
9. **`MapPage` `map_empty_state_shown` event** — listed as "suggested extra" in tracking section. Planner decides whether to ship in v0; recommended for visibility into edge-case navigation.
