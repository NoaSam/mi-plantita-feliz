## Estado anon (intended_action durante el flujo de auth)

| Option | Description | Selected |
|--------|-------------|----------|
| sessionStorage | Sobrevive a navegaciones y reload del browser. Convive con el patrón existente de localStorage para `anonymous_id`. Simple, sin nuevo Context provider. Limpia tras consumir. | ✓ |
| React Context nuevo | Provider en App.tsx con state in-memory. Más limpio conceptualmente. Pero se pierde si el flujo de auth navega a otra ruta o el browser refresca. | |
| Query param en URL | El botón del wall lleva a /login?return_to=/plant/X&action=home. Visible en URL, deep-linkable, pero acopla intención a navegación. | |

**User's choice:** sessionStorage
**Notes:** sessionStorage es el patrón más resiliente al flujo de auth (que puede navegar a /login y volver). Convive bien con el localStorage que ya guarda `anonymous_id`. Clave propuesta `mp_pending_classification` con TTL implícito de 30 minutos para evitar state stale.

## Routing por id (cómo abrir planta desde historial / sección)

| Option | Description | Selected |
|--------|-------------|----------|
| Ruta nueva /planta/:id | React Router ya configurado en App.tsx con rutas /, /mis-plantas, /ajustes. Añadir /planta/:id que carga la fila y monta PlantResultView. Deep-linkable, back button del browser funciona, pattern estándar. | ✓ |
| Modal overlay sobre home | PlantResultView se abre como modal desde Index. Sin nueva ruta. Pero rompe back button (cierra modal vs vuelve atrás) y no es deep-linkable. | |
| Query param en home /?plant=:id | Index detecta el query y monta PlantResultView. Sin nueva ruta. Más ligero pero menos limpio. | |

**User's choice:** Ruta nueva /planta/:id
**Notes:** Es la ruta deep-linkable y respeta el back del browser. Si el id no existe (RLS deny o eliminada), navegar a `/` con toast "Esta planta no existe o ya no está disponible".

## DB timing (cuándo escribimos `context` a la base de datos)

| Option | Description | Selected |
|--------|-------------|----------|
| Inmediato + UPDATE de revert | Tap → UPDATE inmediato a 'home'. UI muestra morph + Deshacer. Si pulsa Deshacer → UPDATE de vuelta a 'unclassified'. Riesgo: 'phantom rows' si la red falla mid-undo, pero el estado es real en DB siempre. | ✓ |
| Diferido 5s, escribe solo si no hay undo | Tap → estado local muestra morph + Deshacer. UPDATE a DB solo a los 5s si no hubo undo. Si Deshacer → cancelar el setTimeout, no escribir. Más eficiente pero el estado UI y DB son inconsistentes durante esos 5s. | |

**User's choice:** Inmediato + UPDATE de revert
**Notes:** Garantiza coherencia cross-device (si el usuario abre la app en otro dispositivo durante los 5s, ve el estado real). Coste adicional: una segunda escritura cuando se hace Deshacer, pero es operación rara. Manejo de errores: si el primer UPDATE falla, cancelar el morph y mostrar toast de error.
