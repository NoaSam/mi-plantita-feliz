## Decisions Made

- **CHECK constraint = 3 valores únicamente.** El SCHEMA-AUDIT inicial mencionaba un cuarto valor `'unsaved'`; SPEC-1 lo descarta. Migration alineada con SPEC.
- **Default `'unclassified'` para todas las filas pre-existentes.** Sin UPDATE manual: fast-path de Postgres ≥11 hace metadata-only ADD COLUMN.
- **Índice parcial con `WHERE user_id is not null`.** Reduce tamaño del índice y limita las queries de surface a usuarios autenticados (filas anónimas nunca aparecen en UI de usuario logged-in).
- **Refactor inline en Task 3, no nuevo hook.** En vez de crear `use-plant-history-with-refetch.ts`, se refactoriza el hook existente para no duplicar el row mapping. Cuando el shape cambie en futuro (por ejemplo añadir `lat`/`lng` al PlantResult), sólo hay un sitio que tocar.
- **`refetch = fetchHistory` (mismo callback).** No se crea wrapper extra; el `useCallback` ya es estable y consumers pueden meterlo en deps de `useEffect` sin loops infinitos.
- **Cast `row.context as union` en lugar de runtime validation.** La CHECK constraint en DB garantiza set membership; el cast es seguro. Documentado en threat model T-02.1-04 como concern para futuras migraciones (si se añade un valor, actualizar CHECK + union juntos).
- **Toaster en `top-center`.** Mobile-first: el bottom queda libre para `BottomTabBar`.
