## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-01 | Tampering | `plant_searches.context` column | mitigate | CHECK constraint `context in ('home','wild','unclassified')` rejects out-of-set values at DB layer. RLS unchanged — `user_id = auth.uid()` already restricts UPDATE to owner. |
| T-02.1-02 | Information disclosure | New composite index `plant_searches_user_context_date` | accept | Index includes `user_id` as leading column; queries against it still pass through RLS. No new disclosure surface — RLS remains the only gate. |
| T-02.1-03 | Denial of service | `ALTER TABLE ADD COLUMN` blocking writes | accept | Postgres ≥11 fast-path `ADD COLUMN ... DEFAULT constant` is metadata-only (no row rewrite). Project size is "docenas a cientos" of rows per SCHEMA-AUDIT § 2; lock window measured in milliseconds. |
| T-02.1-04 | Repudiation | Type cast `row.context as 'home' \| 'wild' \| 'unclassified'` in `usePlantHistory` | accept | Cast is safe because CHECK constraint guarantees set membership at DB layer. If a future migration adds a value, TypeScript narrows incorrectly — captured as a future migration concern in SCHEMA-AUDIT § 4 ("update CHECK + types together"). |
| T-02.1-05 | Information disclosure | Sonner `<Toaster />` rendering arbitrary error messages | mitigate | All error messages are pre-mapped Spanish strings (per `auth.service.ts` `ERROR_MAP`). No raw error from Supabase reaches the user — `use-classify-plant` (Plan 02) will toast the locked string `"No se pudo guardar. Reintenta."` only. |
