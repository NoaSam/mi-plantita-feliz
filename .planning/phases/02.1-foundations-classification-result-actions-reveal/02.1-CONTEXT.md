<decisions>
## Implementation Decisions

### Estado de la intención del anónimo durante el flujo de auth

- **D-01:** El `intended_action` (`'home' | 'wild'`) y el `plant_search_id` se persisten en `sessionStorage` al abrir el `AnonClassificationWall`. Convive con el patrón existente de `localStorage` para `anonymous_id`. Sobrevive a navegaciones a `/login` o `/signup` y a reload del browser durante el flujo de auth. Se limpia explícitamente tras consumir (post-`UPDATE` exitoso de `context`) o si el usuario cierra el wall con "Volver sin guardar".
- **D-02:** Clave de storage propuesta: `mp_pending_classification` con shape `{ plant_search_id: string, action: 'home' | 'wild', anonymous_id: string, ts: number }`. Si pasan más de N minutos (p.ej. 30) entre el tap y el login exitoso, se descarta el intent (evita state stale).

### Organización de los 7 componentes nuevos

- **D-03:** Todos planos en `src/components/`, coherente con el patrón existente (`PhotoCapture`, `PlantResultView`, `LocationConsentModal` también están planos). No se introduce subfolder `classification/` ni `history/` — 7 archivos más no rompen la organización actual y simplifica imports con el path alias `@/components/`.
- **D-04:** Nombres exactos (PascalCase, default export, archivo `.tsx`):
  - `ClassificationCards.tsx`
  - `ClassificationMorph.tsx`
  - `PersistentClassificationBanner.tsx`
  - `UnclassifiedSection.tsx`
  - `HistorySummary.tsx`
  - `ContextChip.tsx`
  - `AnonClassificationWall.tsx`

### Routing para "abrir planta por id"

- **D-05:** Nueva ruta `/planta/:id` registrada en `src/App.tsx` junto a las rutas existentes (`/`, `/mis-plantas`, `/ajustes`). La página carga la fila con `usePlantById(id)` (hook nuevo) y renderiza el mismo componente `PlantResultView` que se usa post-identificación. Deep-linkable, back button del browser funciona, patrón estándar.
- **D-06:** Si el `id` no se encuentra (RLS niega o el id no existe), la ruta navega a `/` con un mensaje toast "Esta planta no existe o ya no está disponible". No se renderiza un 404 dedicado — patrón consistente con la app actual.
- **D-07:** Tap en thumbnail de `UnclassifiedSection` → `navigate(\`/planta/${id}\`)`. Tap en item de `History` → mismo `navigate`. El estado `from` de React Router NO se usa para back specials — el back del browser actúa como esperado.

### Timing de UPDATE en clasificación

- **D-08:** **Inmediato + UPDATE de revert.** Al tocar una `ClassificationCard`: la app ejecuta `update plant_searches set context = X where id = Y` SINCRONAMENTE; al recibir éxito muestra el `ClassificationMorph` con `Deshacer` durante 5000 ms. Si el usuario pulsa `Deshacer` → segundo UPDATE devolviendo `context = 'unclassified'`. Si no pulsa Deshacer → setTimeout colapsa el morph al `PersistentClassificationBanner` sin escritura adicional.
- **D-09:** Manejo de errores de red: si el UPDATE inicial falla, el morph NO se muestra y aparece un toast de error en español ("No se pudo guardar. Reintenta."). El usuario puede tocar la card de nuevo. Cero estado fantasma local.
- **D-10:** Si el usuario navega fuera de la pantalla durante los 5s de undo, el setTimeout se cancela en el `useEffect` de cleanup. La clasificación queda persistida (ya está en DB) y al volver a la pantalla aparece el `PersistentClassificationBanner` (estado real desde DB), no el morph.

### Patrones derivados (no requirieron pregunta — siguen las convenciones del proyecto)

- **D-11:** Hooks nuevos siguen el patrón `use-kebab-case.ts` con export `useFooBar`. Archivos esperados:
  - `src/hooks/use-classify-plant.ts` — UPDATE + tracking + revert
  - `src/hooks/use-unclassified-count.ts` — query del count para `UnclassifiedSection`
  - `src/hooks/use-plant-by-id.ts` — fetch de una planta por id (con manejo de RLS deny)
  - `usePlantHistory.ts` se extiende para incluir `context` en la fila devuelta
- **D-12:** Las queries que dependen de `context` (count del home, lista de history) se invalidan/refetchean tras cada UPDATE local. Sin Supabase realtime — patrón existing es manual refetch.
- **D-13:** `claim_anonymous_searches` RPC se llama post-signup en `auth.service.ts`; tras esa promesa resuelva, el cliente lee `mp_pending_classification` de `sessionStorage`, ejecuta el UPDATE de `context` con la intención, y limpia la clave. Esto se hace en el componente que monta `PlantResultView` tras el redirect de auth, no en `auth.service.ts` (separation of concerns: auth no sabe de clasificación).

### PostHog tracking

- **D-14:** Todos los `track()` calls usan `src/lib/track.ts`. Las propiedades match exactly the contract en `docs/posthog-events.md` § Phase 02.1. `unclassified_section_shown` deduplica con un flag in-memory en el módulo (`let _shownThisSession = false`).
- **D-15:** `anon_searches_claimed` se dispara en `auth.service.ts` justo después de la promesa exitosa del RPC, con `count` extraído de la respuesta del RPC (si la RPC no devuelve count, es necesario consultarlo antes — preguntar al `gsd-planner` si requiere modificar el RPC para devolver count, o asumir count = `<rows con anonymous_id antes>`).

</decisions>

## Existing Code Insights

### Reusable Assets

- **`PlantResultView.tsx`** — Componente de detalle existente. Mantiene Framer Motion, accordion shadcn, sticker shadow. Es el host obvio para inyectar la sección de clasificación. NO duplicar; extender.
- **`src/lib/track.ts`** — Wrapper sobre PostHog con consent gating. Todos los nuevos `track()` calls van por aquí.
- **`src/services/auth.service.ts`** — Ya tiene `claimAnonymousSearches()` cableado al flujo de signin/signup. Extender con un step adicional que procese `mp_pending_classification`.
- **`src/lib/anonymous-id.ts`** — Genera y persiste `anonymous_id` en localStorage. La intención de clasificación va en `sessionStorage` (separada) pero usa el mismo `anonymous_id` para vincular la fila.
- **shadcn `Sheet` component** — Ya disponible vía shadcn. Usar para `AnonClassificationWall` (bottom sheet) en lugar de inventar componente desde cero.
- **`framer-motion`** — Ya en uso en `PlantResultView`. Usarlo para la transición del morph (card → confirmation card → collapse a banner) y para la entrada del bottom sheet.
- **shadcn `Button`** + tokens del system — para todos los CTAs de los nuevos componentes. NO inventar variantes nuevas.
- **`useAuth()` hook** — para detectar logged-in vs anonymous en los componentes (Cards, UnclassifiedSection, History).

### Established Patterns

- **Hooks pattern:** `use-kebab-case.ts` con export camelCase. Hooks nuevos siguen este molde.
- **Service layer:** lógica de negocio en `src/services/` (auth) y `src/lib/` (utilities). El UPDATE de `context` puede vivir en un hook (`use-classify-plant.ts`) que abstrae la query, sin necesidad de service.
- **Error handling:** Spanish user-facing messages. Try/catch con extracción `e instanceof Error ? e.message : "Error desconocido"`. Toast para errores no fatales.
- **Tracking pattern:** `track("event_name", { ...props })` siempre via el helper. PostHog ya inicializa solo con consent.
- **Anonymous flow:** `anonymous_id` en localStorage; al login, `claim_anonymous_searches(p_anonymous_id)` RPC ejecuta el merge. Reutilizar este flujo extendiendolo con el procesamiento del `mp_pending_classification`.
- **localStorage vs sessionStorage:** localStorage usado para state que debe sobrevivir restarts (anonymous_id, consent). sessionStorage para estado de flujo (intención de clasificación) — se limpia con la sesión del browser, evitando state stale a largo plazo.

### Integration Points

- **`Index.tsx`** lee `useAuth()` para condicionar `UnclassifiedSection`. La sección monta `useUnclassifiedCount()` y maneja loading/empty internamente.
- **`PlantResultView.tsx`** acepta una nueva prop `plant` que incluye `context`. Renderiza condicionalmente:
  - `context === 'unclassified'` + `auth.user` → `<ClassificationCards onClassify={...} />`
  - `context === 'unclassified'` + `!auth.user` → `<ClassificationCards onClassify={openWall} />` (mismo componente, diferente handler)
  - `context === 'home' | 'wild'` → `<PersistentClassificationBanner context={...} onChange={...} />` que al cambiar revela las cards de nuevo
  - Después siempre el accordion existente.
- **`History.tsx`** lee la lista con `usePlantHistory()` (extendido) y para cada fila renderiza `<ContextChip context={...} />`. Encima, `<HistorySummary counts={...} />` con agregados.
- **`auth.service.ts`** post-signup/login flow: `claimAnonymousSearches()` → if `mp_pending_classification` exists in sessionStorage → execute UPDATE `context` → clear key → fire `anon_searches_claimed` event.
- **Migration**: `supabase/migrations/2026MMDD000000_add_context_to_plant_searches.sql` aplica via `supabase db push`. Tras eso, regenerar tipos: `supabase gen types typescript --project-id sdxfxkqzgnonxfshbjfc > src/integrations/supabase/types.ts`.

- `Button`, `Card`, `Accordion`, `Dialog`, `Sheet`, `Tooltip`, `Toast` (sonner)
- Todos consumen los tokens en `tailwind.config.ts` + `src/index.css`. NO necesitan extensión.
