## Findings

### IN-01 — Info — No timeout on outbound HTTP fetches in `scripts/benchmark-prompt.ts`
**File:** `scripts/benchmark-prompt.ts`
**Lines:** 142 (Claude), 169 (Gemini), 192 (OpenAI), 251 (image fetch)

The 3 model `fetch()` calls and `fetchImageAsBase64()` have no `AbortSignal.timeout(...)`. If an upstream API hangs, the script hangs indefinitely. The edge function uses `INVOKE_TIMEOUT_MS = 30000` and `SAFETY_TIMEOUT_MS = 45000` for the same calls (see `src/hooks/use-plant-identifier.ts:22-23`).

**Why this is non-blocking:**
- Tool is a local developer/owner CLI run interactively — the operator can `Ctrl-C` if it hangs
- `Promise.allSettled([...])` in `runItem` does not return until all 3 promises settle, but a stalled API would still eventually be aborted by Node's default socket timeout (~2 min on modern Node)
- Per `02-02-PLAN.md` threat-model T-02b-04, quota/runtime concerns are explicitly accepted for this tool

**Recommended (not required):**
Add `signal: AbortSignal.timeout(60_000)` to each `fetch()` call. Trivial to add later if iteration cycles surface real hangs.
